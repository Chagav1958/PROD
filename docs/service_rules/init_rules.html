Правила сервиса Инициализация (Initialize-Project)


Состав сервиса


ФайлНазначение
scripts\Initialize-Project.ps1Однократная настройка путей проекта на новом компьютере

Зависимости


- PowerShell 5.1

- config.json — должен существовать в корне проекта


Известные ошибки и их предотвращение


1. Пути в config.json перезаписываются

- Скрипт модифицирует config.json: заменяет относительные пути на абсолютные

- Важно: если в config.json были пути с .\ (относительные), они будут преобразованы

- Правило: после инициализации проверить config.json в Git diff


2. Кодировка config.json

- Скрипт сохраняет через Set-Content -Encoding UTF8

- Это UTF-8 with BOM

- Правило: ConvertFrom-Json читает с -Encoding UTF8, но другие скрипты используют -Raw


3. Проверка зависимостей

- Get-Command isql — может не найти isql, если Sybase не установлен

- Test-Path "C:\Program Files\Google\Chrome\Application\chrome.exe" — проверка Chrome для PDF

- Правило: пропускать через -SkipChecks если зависимости не критичны


4. Создание директорий

- Создаются: BD, PB_Current, PB_Main, reports\logs, tools

- Правило: при добавлении новых директорий в проект обновить массив $dirs


5. Resolve-RelativePath

- Проверяет только $Path.StartsWith(".\")

- Пути с ..\ не обрабатываются

- Правило: при использовании относительных путей в config.json начинать их с .\


Рекомендации


- Запускать только один раз при переносе проекта на новый компьютер

- После инициализации запустить: .\bin\Prod-GUI.bat

- Проверить, что все пути в Settings → Paths корректны

- Если пароль VSS был зашифрован на другой машине — ввести его заново в Settings → VSS
