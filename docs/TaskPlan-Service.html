Сервис управления планом объёмных задач

TaskPlan Service v1.0 | 19.07.2026 | C:\AIS\AI\Prod\scripts\

1. Назначение

Сервис предназначен для решения объёмных задач с использованием недорогих LLM.

Позволяет:

  • Создать общий план задачи с этапами, статусами и ответственными
  • Отслеживать прогресс выполнения
  • Откладывать сложные подзадачи на дорогую LLM
  • Формировать бриф для дорогой LLM с минимальным контекстом
  • Визуализировать состояние через ДО-индикатор

3. Быстрый старт

# 1. Создать план
> powershell -File TaskPlan-Tracker.ps1 -Action new -TaskName MYTASK -Goal "Цель" -Stages "Этап 1|llm-A","Этап 2|llm-B"

# 2. Отметить этап
> powershell -File TaskPlan-Tracker.ps1 -Action set -TaskName MYTASK -StageNum 1 -Status done -DoneBy llm-A

# 3. Бриф для дорогой LLM
> powershell -File TaskPlan-PrepareBrief.ps1 -TaskName MYTASK -StageNum 2 -Context "описание контекста"

# 4. ДО-индикатор
> powershell -File Show-TaskPlan.ps1 -TaskName MYTASK -Once

4. TaskPlan-Tracker.ps1

4.1. Параметры

ПараметрТипОписание
-Action[new|add|set|show|next|sync]Действие
-TaskNamestringИмя задачи (папка)
-Stagesstring[]Массив этапов. Формат: "Текст" или "Текст|кем"
-StageNumintНомер этапа (1-based)
-Status[todo|wip|done|defer]Статус этапа
-DoneBystringКто/какая LLM выполнил
-GoalstringЦель задачи
-ReleaseRootstringКорень задач (по умолч. C:\AIS\1 Release)
-ForceswitchПерезаписать при new

4.2. Действия

ActionОписание
newСоздать новый план. Требует -Stages и -Goal. С -Force перезаписывает.
addДобавить этапы к существующему плану.
setИзменить статус этапа. Требует -StageNum + -Status.
showПоказать содержимое ПЛАН_РЕАЛИЗАЦИИ.txt.
nextПоказать следующий незавершённый этап.
syncПересинхронизировать plan_state.json из txt.

4.3. Статусы этапов

СтатусМеткаЗначение
todo[ ]Не начат
wip[~]В работе
done[x]Готов
defer[!]Отложен на дорогую LLM

4.4. Примеры

# Создать план с 4 этапами
> powershell -File TaskPlan-Tracker.ps1 -Action new -TaskName SYBASE-12345 `
    -Goal "Реализовать отчёт" -Stages "Анализ|haiku","Разраб|sonnet","Рефакторинг|opus","Тесты|haiku"

# Отметить этап 3 как отложенный
> powershell -File TaskPlan-Tracker.ps1 -Action set -TaskName SYBASE-12345 `
    -StageNum 3 -Status defer -DoneBy "глубокий рефакторинг"

# Показать следующий этап
> powershell -File TaskPlan-Tracker.ps1 -Action next -TaskName SYBASE-12345

7. Структура файлов задачи

<ReleaseRoot>/<TaskName>/
├── Describe/
│   ├── ПЛАН_РЕАЛИЗАЦИИ.txt        — общий план (txt с чек-боксами)
│   ├── plan_state.json             — зеркало для ДО-индикатора
│   ├── <TaskName>_SUB_<n>_бриф.txt — бриф для дорогой LLM
│   ├── <объект>_анализ.txt         — анализ объекта
│   └── <объект>_изменения.txt      — правки объекта
├── Git_YYYY_MM_DD/                — оригиналы объектов
├── Test_YYYY_MM_DD/               — изменённые объекты
└── Ready_YYYY_MM_DD/              — готовые к выгрузке

8. Полный цикл работы

  1. TASK <имя> — создать папку задачи (правило TASK)
  2. new + Stages + Goal — создать общий план
  3. set + Status — отмечать прогресс этапов
  4. PrepareBrief + StageNum — подготовить бриф для дорогой LLM
  5. Запустить дорогую LLM для решения подзадачи
  6. set + Status done — отметить этап выполненным
  7. next — узнать следующий этап
  8. Show-TaskPlan -Once — проверить состояние
  9. Повторять шаги 3-8 до завершения

Все шаги 3-8 выполняются ДЕШЁВОЙ LLM. Дорогая LLM берёт ТОЛЬКО отложенные [!] этапы (шаг 5).

9. Известные ограничения PS 5.1

Bug-PS51-008: Where-Object при 1 результате возвращает объект, а не массив. .Count даёт пустую строку. Исправление: всегда оборачивать в @(Where-Object {...}).Count, а не (Where-Object {...}).Count.
Bug-PS51-009: Хэш-таблицы в Parse-Stage. Where-Object на хэш-таблицах считает все строки как совпадение. Исправление: использовать [PSCustomObject] вместо @{...}.
Bug-PS51-010: ConvertFrom-Json в PS 5.1 не поддерживает -Depth. Исправление: Add-Type -AssemblyName System.Web.Extensions, New-Object System.Web.Script.Serialization.JavaScriptSerializer. Возвращает Dictionary, доступ через $dict['key'].
Bug-PS51-011: Join-Path принимает только 2 пути. Исправление: вложенный вызов: Join-Path (Join-Path $a $b) $c.

10. Связь со стратегией

Сервис реализует раздел «Стратегия решения объёмных задач недорогими/бесплатными LLM» из AGENTS.md:

  • П.2 (Общий план) → TaskPlan-Tracker.ps1 new/add/set
  • П.3 (Поэтапное выполнение) → set/show/next
  • П.4 (Переход на другую LLM) → plan_state.json
  • П.5 (Откладывание на дорогую LLM) → defer статус
  • П.6 (Подготовка перед дорогой LLM) → PrepareBrief.ps1
  • П.7-8 (Роутинг и ДО) → Show-TaskPlan.ps1
