**Дата:** 01.09.2026
**Статус:** восстановлен и протестирован
**Тип документа:** техническая спецификация восстановления сервиса

## 1. Назначение сервиса

Сервис **SqlExport** выполняет выгрузку DDL-объектов базы данных Sybase ASE (сервер `dev_golden`, БД `golden` — «Golden» / боевой контур разработки) в файлы `*.sql`. Объекты разбиваются по категориям в отдельные папки для последующего переноса в Jira-задачи (`SYBASE-*`, `SUPRT-*`) и репозиторий.

**Категории объектов:**
- Хранимые процедуры (`type = 'P'`)
- Функции (`type = 'FN', 'TF'`)
- Триггеры (`type = 'TR'`)
- Таблицы (`type = 'U'`)
- Представления (`type = 'V'`)
- Индексы (все некластерные/кластерные, не PK)
- Первичные ключи (PK)
- Внешние ключи (FK)
- Права доступа (GRANT, из `sysprotects`)

## 3. Причины отказа сервиса (до восстановления)

Экспорт падал с `FATAL`. Выявлены следующие причины:

### 3.1. Отсутствовали генераторы индексов, PK, FK, прав

Файлы `gen_indexes.sql`, `gen_pk.sql`, `gen_fk.sql`, `gen_grants.sql` отсутствовали в `bin\`. Без них при экспорте соответствующих категорий isql получал пустой/некорректный вход и экспорт завершался ошибкой.

**Исправление:** созданы все четыре скрипта (см. п. 2). Учтены правила Sybase ASE:
- `DECLARE CURSOR` обязан быть **единственным оператором в батче** (отделён `go`). Иначе — ошибка компиляции.
- Конкатенация строк в `PRINT` не поддерживается: используется `select @msg = '...' + ...`, затем `print @msg`.
- `SET NOCOUNT ON` добавлен в начало каждого скрипта — иначе в выход попадают служебные строки `(1 row affected)`.

### 3.2. Ошибка синтаксиса bat в циклах `for /f`

В `SQL_exp_param.bat` в циклах экспорта применялась конструкция `(echo ...) > файл` внутри тела `for /f ... do (...)`. Вложенные скобки не экранировались → cmd выдавал `Недопустимый параметр: text).` и прекращал обработку объектов.

**Исправление:** в строках, формирующих SQL-файлы, любые `(` и `)` экранируются `^(` и `^)`, либо используется запись `echo строка>>файл` без обрамляющих скобок.

**Проверено:** минимальные тесты `temp\test_for_parens.bat` — вывод корректен, ошибок нет.

### 3.3. Битые комментарии и неправильная кодировка bat

Кириллические комментарии в `SQL_exp_param.bat` хранились в неверной кодировке → кракозябры. Bat-файл должен быть **Windows-1251 (ANSI), CRLF, без BOM**.

**Исправление:** файл пересобран в CP1251 + CRLF, повреждённые строки переписаны.

### 3.4. Отсутствовала валидация OBJECT_TYPE

При невалидном значении объектного типа bat не сообщал об ошибке.

**Исправление:** добавлена проверка (строки ~96–100):
```bat
if not "%OBJECT_TYPE%"=="" (
    echo FATAL: Unknown OBJECT_TYPE: %OBJECT_TYPE%
    exit /b 1
)
```

### 3.5. Конфликт счётчиков Triggers и Tables

Обе секции использовали переменные `T_CNT` / `T_OK` (процедуры → `P_*`, функции → `F_*`, триггеры → `T_*`, таблицы → снова `T_*`). В финальном счётчике выводился заниженный итог: `Found: 2133` вместо `2250` (триггеры не учитывались, таблицы — дважды).

**Исправление:** таблицы переведены на собственные переменные `TB_CNT` / `TB_OK`, суммы пересчитаны:
```bat
set /a TOTAL_OK = P_OK + F_OK + T_OK + TB_OK + V_OK + I_OK + PK_OK + FK_OK + G_OK
set /a TOTAL_CNT = P_CNT + F_CNT + T_CNT + TB_CNT + V_CNT + I_CNT + PK_CNT + FK_CNT + G_CNT
```

### 3.6. Шапка лога не записывалась (в логе не было `Started`)

В `SQL_exp_param.bat` папка `LOGS` создавалась командой `mkdir "%BASEDIR%\LOGS"` (строка ~49) **после** записи заголовка в лог (строки ~24–28). При первом запуске папки не существовало → первая команда `echo ... > "%LOGFILE%"` падала, и в лог попадала только часть (без шапки `SQL OBJECTS EXPORT / Task / Started`).

**Исправление:** `mkdir "%BASEDIR%\LOGS" 2>nul` добавлено сразу перед `set LOGFILE=...` — папка гарантированно существует до первой записи. Проверено: заголовок и `Started: <дата> <время>` присутствуют в логе при каждом прогоне.

### 3.7. Неверный exit code (всегда возвращал 0)

В финальном блоке `set /a TOTAL_FAIL=TOTAL_CNT-TOTAL_OK` вычислялся **до** установки `TOTAL_CNT` (TOTAL_CNT была ещё не определена → 0). Как следствие:
- при успешном прогоне `TOTAL_FAIL` мог стать `-1` (категорийные запуски: 0 − OK);
- сервис не мог сигнализировать CLI/GUI об ошибках через код возврата.

**Исправление:** порядок строк изменён: сначала `TOTAL_OK`, затем `TOTAL_CNT`, затем `TOTAL_FAIL = TOTAL_CNT − TOTAL_OK`. Теперь `exit 0` при полном успехе, `exit > 0` при сбоях. Проверено на категорийных и негативных тестах.

## 4. Правила, используемые при экспорте

### 4.1. Правила Sybase ASE (для генераторов)

- `DECLARE CURSOR` — только собственный батч.
- `PRINT` — только после присвоения переменной через `select @msg = ...`.
- `SET NOCOUNT ON` обязателен.
- Просмотр текста объектов — через `syscomments` (он содержит hex-представление для длинных объектов) с разбивкой по `number, colid` и последующей сборкой скриптом `Rebuild-Object.ps1` (фрагменты до 65535 байт возвращаются isql с `convert(varbinary(255), text)`).
- Имена объектов выбираются через `sysobjects` с фильтром `user_name(uid)='dbo'`.

### 4.2. Правила cmd/bat

- Внутри `for /f ... do ( ... )` скобки в тексте `echo` экранировать `^(` `^)`.
- Работа с in-place переменными внутри цикла — только с `setlocal enabledelayedexpansion` и `!VAR!`.
- Файлы `.bat`, `.sql` — Windows-1251 (ANSI), CRLF, без BOM.
- Скрытый запуск из PS — только `-NoLogo` (без `-NoProfile`, Bug-046 кракозябр).
- Если скрипт содержит `$`, `{}`, вложенные кавычки — вызывать через `-File script.ps1`.

### 4.3. Кодировки выходных файлов

| Часть | Кодировка |
|-------|-----------|
| Исходные генераторы `.sql` (в `bin\`) | Windows-1251, LF/CRLF |
| Выходные файлы `.sql` | Windows-1251 (ANSI), CRLF — выполняет `Convert-ExportEncoding.ps1` |
| `.bat` | Windows-1251, CRLF, без BOM |
| PowerShell `.ps1` | UTF-8 **с BOM** (в проекте: `scripts\Add-Bom.ps1`) |

## 5. Параметры вызова

```
SQL_exp_param.bat Server Database Password [TaskName] [ExportPath] [OBJECT_TYPE]
```

- `Server` — Sybase ASE (напр. `dev_golden`)
- `Database` — БД (напр. `golden`)
- `Password` — пароль пользователя `vchaga`
- `TaskName` — имя Jira-задачи (для лога и описаний)
- `ExportPath` — необязательный; по умолчанию `<bin>\..\BD\<Server>\<Database>`
- `OBJECT_TYPE` — один из: `Procedure`, `Functions`, `Triggers`, `Tables`, `Views`, `Indexes`, `PK`, `FK`, `Grants`. Пусто → полный экспорт всех категорий.

Через dotnet-обёртку (используется для прогресс-бара в GUI):

```
dotnet run --project C:\AIS\AI\Prod\scripts\SqlExport\SqlExport.csproj -c Release -- <server> <db> <password> <ExportPath> [objectType]
```

Пароль для штатной работы берётся из `C:\AIS\AI\Prod\config\.local_secrets.json` (DPAPI, контейнер `AIS.Secrets.2026`). Значение `sqlsql` используется только в локальных тестах.

### 6.1. Дельты в категории Tables (кириллическое имя)

При проверке полного экспорта v2 обнаружено: в `tables.txt` (лог сводного списка) 824 строки, но на диске в `Tables\` было **823** файла — не хватало файла для таблицы с кириллическим именем (импорт из Excel, имя `Лист1` / hex `cb e8 f1 f2 31` в CP1251).

Повторный изолированный прогон категории `Tables` (папка `temp\sql_tables3`) создал все **824** файла, включая `Лист1.sql` (заголовок файла корректен, `EXIT=0`). Итог: экспорт таблиц работает полностью; потеря файла в полном прогоне единична и связана с обработкой кириллического имени в `cmd /c for /f` (см. п. 8).

## 7. Инструкция по восстановлению (быстрая починка)

Если сервис снова выдаёт `FATAL`:

1. Проверить наличие всех 5 генераторов в `bin\`: `gen_create_table.sql`, `gen_indexes.sql`, `gen_pk.sql`, `gen_fk.sql`, `gen_grants.sql`.
2. Проверить `bin\SQL_exp_param.bat`: каждая категория, каждого `echo ... ( ... )` внутри `for` — скобки экранированы; кодировка CP1251+CRLF без BOM.
3. Проверить присутствие `set nocount on` в начале каждого генератора.
4. Проверить, что `Convert-ExportEncoding.ps1` в `export_cleanup` вызывается с `-Extensions "*.sql"`.
5. Проверить порядок итоговых счётчиков в `SQL_exp_param.bat` (БАГ-3.7): `TOTAL_OK`, затем `TOTAL_CNT`, затем `TOTAL_FAIL = TOTAL_CNT − TOTAL_OK` — иначе exit code всегда 0.
6. Проверить, что `mkdir "%BASEDIR%\LOGS" 2>nul` стоит до `set LOGFILE=...` (БАГ-3.6) — иначе в лог не попадает шапка `Started`.
7. Ручной тест одной категории:
   ```bash
   cmd /c "C:\AIS\AI\Prod\bin\SQL_exp_param.bat" dev_golden golden <пароль> TEST C:\AIS\AITemp Indexes
   ```
   Ожидание: папка `Indexes\all_indexes.sql` без `(1 row affected)`, в логе шапка с `Started`, exit 0.
8. Только после успеха категорий — полный экспорт.

## 8. Известные ограничения

- Экспорт по объектам выполняется последовательно; полный экспорт БД `golden` занимает ~30–40 минут.
- Имена объектов с **кириллицей** (например, `Лист1` после импорта из Excel) могут нестабильно выгружаться в **полном** прогоне через `cmd /c` bat (кодировка имени в цикле `for /f`). В изолированном прогоне категории `Tables` такая таблица создаётся корректно. При расхождении «найдено / файлов на диске» — повторить прогон соответствующей категории.
- `syscomments` хранит только текст объектов (не форматы и не структуру окон PB).
- Для PB-объектов (.sr*) используется **другой** контур (`PB_Current`, `C:\SRC125\gold`) — сервис SqlExport их не затрагивает.
- Пароль в аргументах командной строки виден в выводе процессов; штатно — через `config\.local_secrets.json`.
