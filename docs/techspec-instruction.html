Инструкция: Создание технических спецификаций в формате Markdown


1. Обзор


Техническая спецификация (techspec) — документ, описывающий что, зачем и как будет реализовано в задаче. Формат Markdown обеспечивает:

- Версионирование через Git

- Конвертацию в HTML/PDF

- Читаемость как человеком, так и AI-агентами


---


2. Структура документа


2.1 Шапка (обязательно)


# Техническая спецификация: [Название задачи]



| Поле | Значение |

|------|----------|

| **Задача** | SYBASE-XXXX / BSI-XXXX |

| **Статус** | Черновик / Утверждён / В работе / Завершено |

| **Дата** | ДД.ММ.ГГГГ |

| **Платформа** | AIS (Sybase + PowerBuilder) |

| **Автор** | ФИО |

2.2 Секции (порядок обязателен)


#СекцияНазначение
1КОНТЕКСТПроблема, связи, источники
2AS-ISТекущее состояние (объекты, данные, логика)
3TO-BEЦелевое состояние (блоки, DDL, код)
4ЗАТРОНУТЫЕ СИСТЕМЫВлияние на другие системы
5РИСКИРиски и снижение
6КРИТЕРИИ ПРИЁМКИПродуктовые (AC) и технические (TAC)
7ДЕКОМПОЗИЦИЯUS и подзадачи
8ПРИЛОЖЕНИЯDDL, код, скриншоты, TQ

---


3. Правила оформления


3.1 Заголовки


# Заголовок 1 — название задачи

## Заголовок 2 — секция (КОНТЕКСТ, AS-IS, TO-BE)

### Заголовок 3 — подсекция (Блок 1, Объекты, Данные)

#### Заголовок 4 — элемент (Таблица, DDL, Код)

Правило: Не более 4 уровней вложенности.


3.2 Таблицы


| Колонка 1 | Колонка 2 | Колонка 3 |

|-----------|-----------|-----------|

| Значение 1 | Значение 2 | Значение 3 |

Правило: Всегда указывайте заголовки таблицы.


3.3 Код


Однострочный код:

`имя_объекта`

Блок кода (SQL):



-- SQL-код


SELECT * FROM table






Блок кода (PowerShell/PB):




// Псевдокод PB


dw_list.Retrieve()






Блок кода (DDL):




-- DDL


ALTER TABLE table_name ADD column_name type






3.4 Списки




Маркированный список:


- Элемент 1

- Элемент 2

- Элемент 3






Нумерованный список:


1. Шаг 1

2. Шаг 2

3. Шаг 3






Чек-лист:


- [ ] Задача не начата

- [x] Задача выполнена






3.5 Ссылки




[Текст ссылки](URL)






3.6 Выделение




**жирный текст**

*курсив*

`код`

5. Интеграция с инструментами




5.1 Поиск объектов




# Поиск объекта

ais-objects_search_objects(query="имя объекта")



# Получение информации об объекте

ais-objects_get_object(name="имя объекта", src="current")



# Сравнение объектов

ais-objects_compare_objects(name="имя объекта", kind="PB")






5.2 Сохранение знаний




# Сохранение в ais-catalog (для проекта AIS)

ais-catalog_save_knowledge(text="описание", tags="теги")



# Сохранение в opencode-mcp (для OpenCode)

opencode-mcp_save_knowledge(text="описание", tags="теги")






5.3 Конвертация в HTML/PDF




# Конвертация всех .md файлов в docs/

powershell -NoLogo -File scripts\Convert-Docs.ps1

6. Чек-лист перед утверждением




6.1 Содержание


- [ ] Шапка заполнена (задача, статус, дата, платформа, автор)


- [ ] Все 8 секций присутствуют


- [ ] Контекст описан (проблема, связи, источники)


- [ ] AS-IS описан (объекты, данные, логика)


- [ ] TO-BE описан (блоки, DDL, код)


- [ ] Затронутые системы перечислены


- [ ] Риски описаны


- [ ] Критерии приёмки заполнены


- [ ] Декомпозиция создана




6.2 Техническое


- [ ] DDL проверены (синтаксис Sybase)


- [ ] Код проверен на совместимость с PS 5.1


- [ ] Ссылки на объекты корректны


- [ ] Таблицы оформлены правильно




6.3 Формат


- [ ] Заголовки иерархичны (не более 4 уровней)


- [ ] Код выделен в блоки с указанием языка


- [ ] Таблицы имеют заголовки


- [ ] Списки оформлены правильно




6.4 Процесс


- [ ] TQ закрыты (если есть)


- [ ] Документ сохранён в C:\AIS\AI\Test\Specs\


- [ ] Документ сконвертирован в HTML/PDF


- [ ] Знания сохранены в MCP

8. Частые ошибки




ОшибкаРешение
Нет шапкиВсегда начинайте с шапки
Неправильный порядок секцийСледуйте порядку 1-8
Код без выделенияИспользуйте ``sql или ``powershell
Таблица без заголовковВсегда указывайте заголовки
Смешанные языкиRussian + English terms (технические термины)
Нет DDL для изменений таблицВсегда добавляйте ALTER TABLE
Нет критериев приёмкиЗаполняйте AC и TAC
