Руководство пользователя ДО TaskPlan


Назначение


ДО TaskPlan — диалоговое окно управления планами объёмных задач. Позволяет создавать задачи, отслеживать этапы, переключаться между LLM, готовить брифы для дорогих моделей.


---


Запуск ДО


Команда `TaskPl`

# В PowerShell или в строке команд OpenCode

TaskPl

Или напрямую:

powershell -NoLogo -File scripts\Show-TaskPlanGUI.ps1 -TaskName SYBASE-12345

При запуске ДО открывается в центре экрана. Окно без рамки, с прозрачностью, можно перетаскивать за заголовок.

Вкладка «Список задач»


Назначение

Показывает текущее состояние всех этапов задачи с цветовой индикацией.


Внешний вид

┌──────────────────────────────────────────────────┐

│ Задача: SYBASE-19371                    [⟳ Обновить]

├──────────────────────────────────────────────────┤

│ [████████████████████░░░░░░░░] 68%                │

│ Всего: 5 | Готово: 3 [x] | В работе: 1 [~]      │

│ Отложено: 1 [!] | Прогресс: 68%                 │

├────┬───────────┬─────────────────────┬───────────┤

│ №  │ Статус    │ Этап                │ Кем/LLM   │

├────┼───────────┼─────────────────────┼───────────┤

│ 1  │ [x] готово│ Анализ объекта      │ deepseek  │

│ 2  │ [x] готово│ Правка SQL          │ llama-3   │

│ 3  │ [~] в раб.│ Тестирование        │ gpt-4o-mi │

│ 4  │ [ ] не нач│ Вывод в ПРОД        │           │

│ 5  │ [!] отлож.│ Сложный рефакторинг │ (бриф)    │

└────┴───────────┴─────────────────────┴───────────┘

Цветовая маркировка строк

- Зелёный [x] готово — этап выполнен

- Жёлтый [~] в работе — этап в процессе

- Красный [!] отложено — этап отложен на дорогую LLM

- Серый [ ] не начато — этап не начат


Прогресс-бар

- Показывает процент выполнения (готово / всего)

- Обновляется при нажатии кнопки «⟳ Обновить»

- Автоматически обновляется после операций на вкладке «Управление»

Вкладка «Управление»


Назначение

Создание плана, изменение статусов, управление этапами.


Поля ввода


Первая строка: Имя задачи + Корень

┌──────────────────────┬──────────────────────────────┐

│ Имя задачи           │ Корень задач                 │

│ ┌──────────────────┐ │ ┌──────────────────────────┐   │

│ │ SYBASE-19371  ▼  │ │ │ C:\AIS\1 Release        │   │

│ └──────────────────┘ │ └──────────────────────────┘   │

└──────────────────────┴──────────────────────────────┘

- Имя задачи — ComboBox с историей + возможность ввода

- История загружается из task_index.json

- Можно ввести новое имя (SYBASE-, SUPRT-, TASK-*)

- Корень задач — автоматически определяется:

- C:\AIS\1 Release — для SYBASE-/SUPRT-

- C:\AIS\AI\Prod\tasks — для остальных


Вторая строка: Цель (Goal)

│ Цель задачи (Goal)                                │

│ ┌──────────────────────────────────────────────┐  │

│ │ Правка отчёта комиссии: добавить фильтр по    │  │

│ │ подразделению и новый столбец с процентом     │  │

│ └──────────────────────────────────────────────┘  │

Третья строка: Этапы

│ Этапы (каждый с новой строки, можно "Текст|Кем") │

│ ┌──────────────────────────────────────────────┐  │

│ │ 1. Анализ объекта usp_report|deepseek-v3     │  │

│ │ 2. Правка процедуры|llama-3-70b              │  │

│ │ 3. Тестирование|gpt-4o-mini                  │  │

│ │ 4. Вывод в ПРОД                              │  │

│ │ 5. Сложный рефакторинг|opus (бриф)           │  │

│ └──────────────────────────────────────────────┘  │

Формат этапов:

- Простой: Текст этапа

- С исполнителем: Текст этапа|исполнитель

- Примеры:

- Анализ usp_report

- Правка процедуры|deepseek-v3

- Тестирование|gpt-4o-mini


Четвёртая строка: LLM + Статус + Номер

┌──────────────────────┬────────────────────┬─────────────┐

│ LLM / исполнитель    │ Статус этапа       │ Номер этапа │

│ ┌──────────────────┐ │ ┌──────────────┐   │ ┌─────────┐ │

│ │ deepseek-v3   ▼  │ │ │ в работе  ▼  │   │ │ 3       │ │

│ └──────────────────┘ │ └──────────────┘   │ └─────────┘ │

└──────────────────────┴────────────────────┴─────────────┘

- не начато → внутри todo

- в работе → внутри wip

- готово → внутри done

┌────────────┬────────────┬────────────┬────────────┬────────────┬────────────┐

Кнопка «Новый план»

Когда нажимать: при создании новой задачи.


Что делает:

1. Создаёт папку задачи

2. Создаёт Describe\ПЛАН_РЕАЛИЗАЦИИ.txt с чек-боксами

3. Создаёт Describe\plan_state.json — зеркало для ДО


Пример:

Имя задачи: TASK-1

Цель: Тестовая задача для проверки TaskPlan

Этапы:

  Анализ требований|deepseek-v3

  Разработка|llama-3-70b

  Тестирование

  Документация

→ Нажать «Новый план» → папка C:\AIS\AI\Prod\tasks\TASK-1 создана.


Кнопка «Уст. статус»

Когда нажимать: для изменения статуса конкретного этапа.


Порядок:

1. Выбрать номер этапа (например, 1)

2. Выбрать статус (например, в работе)

3. Выбрать LLM/исполнителя (например, deepseek-v3)

4. Нажать «Уст. статус»


Результат: в ПЛАН_РЕАЛИЗАЦИИ.txt этап 1 получает [~], а plan_state.json обновляется.


Кнопка «Доб. этапы»

Когда нажимать: для добавления новых этапов к существующему плану.


Пример:

В поле "Этапы" ввести:

  Дополнительное тестирование|gpt-4o-mini

  Ревью кода

→ Нажать «Доб. этапы» → этапы добавлены в конец плана.

Кнопка «След. этап»

Когда нажимать: чтобы найти первый неготовый этап.


Результат: в лог-строке появляется сообщение:

[3] Тестирование (статус: todo)

Кнопка «Подг. бриф»

Когда нажимать: для подготовки брифа на дорогую LLM.


Условие: должен быть этап со статусом отложено [!].


Пример:

Имя задачи: SYBASE-19371

Номер этапа: 5

→ Нажать «Подг. бриф»

Результат: в Describe\ создаётся файл SYBASE-19371_SUB_1_бриф.txt с:

- Описанием этапа

- Контекстом задачи

- Рекомендациями по выбору LLM

- Бюджетом


Кнопка «Синхр. JSON»

Когда нажимать: если plan_state.json устарел или повреждён.


Результат: пересборка JSON из текстового ПЛАН_РЕАЛИЗАЦИИ.txt.

12. Удаление тестового плана

14. Поиск окна GUI (Automation)

15. Закрытие GUI

Ситуация: этап 1 выполнен на deepseek-v3, теперь нужно продолжить на llama-3-70b.

→ Уст. статус

Статус: в работе

LLM / исполнитель: llama-3-70b

→ Уст. статус

Шаг 3. Проверить через «След. этап» — должно показать этап 2.

Сценарий 3: Откладывание сложного этапа на дорогую LLM


Ситуация: этап 4 слишком сложен для дешёвой LLM (требуется глубокий рефакторинг).


Шаг 1. Отметить этап как отложенный:

Номер этапа: 4

Статус: отложено

LLM / исполнитель: opus (будет позже)

→ Уст. статус

Шаг 2. На вкладке «Список задач» увидеть [!] у этапа 4.


Шаг 3. Подготовить бриф:

Номер этапа: 4

→ Подг. бриф

Шаг 4. В папке Describe\ появится файл _SUB_1_бриф.txt.


Шаг 5. Переключиться на дорогую LLM (opus) через DLLM.


Шаг 6. Прочитать бриф и продолжить работу.


---


Сценарий 4: Возобновление задачи после остановки


Шаг 1. Запустить ДО с именем задачи:

# или

Шаг 2. На вкладке «Список задач» увидеть текущее состояние.


Шаг 3. Найти первый неготовый этап: «След. этап».


Шаг 4. Установить статус «в работе» и выбрать LLM.


Шаг 5. Продолжить выполнение.

Сценарий 5: Переключение между несколькими задачами


Шаг 1. Создать задачу А:

Имя задачи: TASK-A

→ Новый план

Шаг 2. Создать задачу Б:

Имя задачи: TASK-B

Шаг 3. Переключиться на задачу А:

Имя задачи: TASK-A

Советы и рекомендации


1. Всегда указывайте LLM при установке статуса — это сохраняет историю исполнителей.

2. Используйте «|Кем» в этапах — тогда при создании плана сразу видно, кто будет выполнять.

3. Бриф перед дорогой LLM — всегда готовьте бриф через «Подг. бриф», это экономит токены.

4. Синхронизация JSON — если ДО показывает устаревшие данные, нажмите «Синхр. JSON».

5. Проверяйте тесты — перед важными изменениями запускайте тесты на вкладке «Тесты».
