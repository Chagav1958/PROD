# Руководство по рабочим пространствам задач и продолжению работы в ПРОД

> **Версия:** 1.0 от 10.09.2026
> **Назначение:** практическая инструкция для запуска новых задач (SYBASE, SUPRT, BSI), продолжения остановленных задач, параллельной работы над несколькими задачами и продолжения разработки сервисов проекта ПРОД.

---

## 1. Введение

Проект ПРОД (`C:\AIS\AI\Prod`) — это единое рабочее место автоматизации подготовки релизов страхового продукта. В нём сосредоточены сервисы, скрипты, правила и базы знаний. Задачи из Jira (SYBASE, SUPRT, BSI) ведутся в отдельных папках выпуска `C:\AIS\1 Release`, а сама разработка сервисов — в ПРОД.

Чтобы задачи не мешали друг другу и любую сессию могла продолжить другая модель, принята трёхуровневая архитектура рабочих пространств.

---

## 2. Архитектура рабочих пространств

| Уровень | Расположение | Что содержит | Кто изменяет |
|---------|--------------|--------------|--------------|
| Глобальный | Конфигурация OpenCode (`C:\Users\vchaga\.config\opencode`) | Провайдеры, модели, агенты, MCP-серверы, LSP-серверы, плагины, глобальные правила | Администратор OpenCode (редко) |
| Общий | `C:\AIS\AI\Common` | Общие правила, шаблоны, документация, словари | Все команды (согласованно) |
| Задачный | Папка задачи в выпуске (см. раздел 3) | Оригиналы, изменённые объекты, описания, план | Сессия, работающая над задачей |

### 2.1. Глобальный уровень

Глобальная конфигурация OpenCode одна на все сессии. Здесь настраиваются:

- провайдеры и модели (включая подписку OpenCode Go, провайдер RouterAI и другие);
- агенты (основные и вспомогательные), общие агенты — в папке `C:\Users\vchaga\.config\opencode\agents\`;
- MCP-серверы: `ais-catalog`, `ais-objects`, `opencode-mcp`, `rules-mcp`, `sybase-docs`, `atlassian`, `ews`;
- LSP-сервер по языку PowerBuilder (`pb-lsp`);
- плагины: автосохранение промптов, русская сводка сессий, интеграция с Claude Code, защита от циклов правок, отслеживание прогресса задач, watchdog.

Изменения на этом уровне делает человек в диалоге с моделью по специальному правилу настройки OpenCode. Правила проекта при этом не затрагиваются.

### 2.2. Общий уровень

Каталог `C:\AIS\AI\Common` содержит то, что применимо ко всем задачам и сервисам:

- общие правила работы с кодировками, безопасностью, командой `ЗАПОМНИ`;
- шаблоны планов реализации и брифа для дорогих моделей;
- общий словарь сокращений и глоссарий;
- общую документацию по работе с задачами.

Правила из ПРОД (`C:\AIS\AI\Prod\AGENTS.md` и файлы `C:\AIS\AI\Prod\.opencode\*.mdc`) уже являются общими для сессий, запущенных внутри ПРОД. Для задач вне ПРОД следует ссылаться на общий уровень либо на правила ПРОД через путь.

С 10.09.2026 эталон общих правил хранится в `C:\AIS\AI\Common`. Рабочие копии в ПРОД синхронизируются со эталоном скриптом `C:\AIS\AI\Common\scripts\Sync-CommonRules.ps1` (режимы `-Compare`, `-Capture`, `-Push` — подробности в `C:\AIS\AI\Common\README.md`).

### 2.3. Задачный уровень

Каждая задача получает собственную папку (правило TASK), а работа по ней ведётся в отдельной сессии OpenCode, открытой в соответствующем рабочем пространстве. Объекты задачи никогда не правятся в «чужой» папке.

## 3. Определение типа задачи

Перед стартом надо убедиться, относится ли запрос к задаче или это короткая операция.

| Ключ задачи | Корневой путь    | Пример папки |
|-------------|------------------|--------------|
| SYBASE-*    | `C:\AIS\1 Release` | `C:\AIS\1 Release\SYBASE-19371_19365` |
| SUPRT-*     | `C:\AIS\1 Release` | `C:\AIS\1 Release\SUPRT-12345` |
| BSI-*       | Выпуск или отдельное пространство | `C:\AIS\1 Release\BSI-9729` |
| Прочие задачи | `C:\AIS\AI\Prod\tasks` | `C:\AIS\AI\Prod\tasks\TASK-1` |

Признаки объёмной задачи (достаточно любого):

- пользователь назвал её задачей или дал имя (ключ SYBASE, SUPRT, BSI);
- ожидается более трёх самостоятельных этапов;
- затрагивает более трёх объектов PowerBuilder или SQL, или несколько папок.

Если запрос короткий (один объект, быстрый ответ) — решение выполняется сразу, без имени и плана.

## 4. Запуск новой задачи

### 4.1. Команда TASK

`TASK <имя_задачи> [<папка>]`

1. Определяется корневой путь: SYBASE и SUPRT — `C:\AIS\1 Release`, остальные — `C:\AIS\AI\Prod\tasks`. Явная `<папка>` переопределяет автовыбор.
2. Поиск существующей папки, начинающейся с имени задачи и суффикса: `<имя_задачи>_*`. Если такая папка есть — работаем в ней, новую не создаём. Папку с точным именем создаём только при отсутствии папки с суффиксом.
3. Суффикс `_<число>` после имени — ключ родительской задачи, в которой лежит техническое задание (например, `SYBASE-19371_19365`). Или `_ТЗ`.

### 4.2. Создание структуры папки задачи

В папке задачи создаются:

| Папка | Назначение |
|-------|-----------|
| `Git_YYYY_MM_DD` | Автовыгрузка оригиналов (SQL из `dev_golden`, PB — копия из PB-библиотек). При неизвестном списке объектов — запросить у пользователя или прочитать из Jira |
| `Test_YYYY_MM_DD` | Готовые объекты для сборки и передачи тестировщикам. Сюда попадают только готовые объекты (диагностические — отдельно!). Если папка за дату уже существует — создаём `Test_YYYY_MM_DD__hh_mm` |
| `DIAG_YYYY_MM_DD_hh_mm` | Объекты для диагностики с временными сообщениями (DIAG-N). Обязательно с датой и временем в имени. Инструкцию по тестированию — в файле .md внутри папки |
| `Ready_YYYY_MM_DD` | Готовые объекты — только по команде после тестирования |
| `Read_YYYY_MM_DD` | Объекты, готовые к выводу в продакшн |
| `Describe\` | Анализ, план реализации и описания изменений по каждому объекту |

### 4.3. План реализации

Для объёмной задачи обязательно создаётся `ПЛАН_РЕАЛИЗАЦИИ.txt` в папке задачи:

- цель и статус (в работе / отложено / завершено);
- этапы с чек-боксами: `[ ]` не начат, `[~]` в работе, `[x]` готов, `[!]` отложен на дорогую модель;
- у каждого этапа — краткий результат и отметка, какой моделью выполнен;
- раздел «СЛЕДУЮЩИЙ ШАГ» — с чего продолжить;
- раздел «ОЧЕРЕДЬ ДОРОГИХ ПОДЗАДАЧ» — список отложенных этапов с обоснованием.

Дубли статуса плана: сводная запись в `ais-catalog` и якорь в `C:\AIS\AI\Prod\rules\pending-tasks.md`.

### 4.4. Автовыгрузка оригиналов

- SQL: выгрузка из `dev_golden` через `C:\AIS\AI\Prod\bin\SQL_exp_single.bat` для каждого объекта.
- PB: копирование из библиотек текущей разработки или из продакшн-референса `C:\SRC125\gold\<библиотека>\`.

## 5. Продолжение остановленной задачи

Продолжение допускается только по явной команде пользователя («продолжить SYBASE-19371»). Автопродолжение запрещено.

Порядок действий:

1. **Знания в первую очередь:** поиск по `ais-catalog` (теги имени задачи, названия объектов) и проверка бизнес-правил.
2. **Прочитать папку задачи** по правилу TASK (раздел 4.1): найти папку с суффиксом, затем прочитать `Describe\` и план.
3. **Продолжить с раздела «СЛЕДУЮЩИЙ ШАГ»** в плане реализации.
4. При переносе папки (например, на `<имя>_*`): перенести все файлы задачи в правильную папку, обновить ссылки в `C:\AIS\AI\Prod\rules\pending-tasks.md` и в базе знаний, удалить ошибочную папку.

## 6. Параллельная работа над несколькими задачами

Параллельная работа возможна за счёт разделения рабочего пространства по задачам:

1. Каждая задача ведётся в своей папке и своей сессии OpenCode. Общие правила, кодировки, безопасность наследуются из ПРОД/общего уровня.
2. В одной сессии не ведутся две задачи с разными папками и разными планами. При необходимости — закрыть одну задачу по правилу остановки (раздел 9) и открыть вторую.
3. Базы знаний разделяются по назначению: всё о проекте AIS (объекты, бизнес-логика, задачи Jira, Sybase, PowerBuilder) — в `ais-catalog`; всё об OpenCode как инструменте (скрипты, диалоговые окна, ошибки конфигурации) — в `opencode-mcp`.
4. При исчерпании ресурса одной модели — зафиксировать текущий этап (результат и «СЛЕДУЮЩИЙ ШАГ») в плане, базе знаний и `C:\AIS\AI\Prod\rules\pending-tasks.md`, затем продолжить на другой модели по явной команде.
5. Дорогие и мощные модели запускаются точечно — только на подзадачи, отложенные в «ОЧЕРЕДЬ ДОРОГИХ ПОДЗАДАЧ», и только после максимальной подготовки (готовый бриф в `Describe\<имя>_SUB_<n>_бриф.txt`).
6. Сессии ПРОД именуются по шаблону `<ключ> YYYY-MM-DD HH:MM` (например, `SUPRT-19100 2026-09-10 14:32`) — дата и время отличают повторные запуски одной задачи. При перезапуске использовать тот же ключ с новой датой и временем; возобновление идёт по команде «продолжить SUPRT-19100». Окно без задачи называть `PROD` (сервисы). Автоматическое переименование выполняет проектный плагин `C:\AIS\AI\Prod\.opencode\plugins\task-session-rename.js`: при вводе «TASK <ключ>» сессия получает имя по шаблону без ручного действия; повторный ввод того же ключа не меняет заголовок.

## 7. Продолжение разработки сервисов в ПРОД

Разработка сервисов (скрипты PowerShell, диалоговые окна, серверы, плагины) ведётся в `C:\AIS\AI\Prod` по общим правилам:

- пути — только через `C:\AIS\AI\Prod\config\config.json`;
- изменения — только внутри `C:\AIS\AI\Prod\` (bin, scripts, config, docs, reports, temp);
- библиотеки PowerBuilder `C:\SRC125\gold` — только для чтения;
- секреты — только в `C:\AIS\AI\Prod\config\.local_secrets.json`, который никогда не попадает в Git;
- кодировки: `.ps1` — UTF-8 с BOM, `.json`/`.jsonc` — UTF-8 без BOM, `.sql` и `.bat` — Windows-1251, `.md` — UTF-8 без BOM;
- запуск PowerShell — всегда через `powershell -NoLogo [-File script.ps1]`, без `-NoProfile`;
- после записи `.ps1` — прогнать `C:\AIS\AI\Prod\scripts\Add-Bom.ps1` или `C:\AIS\AI\Prod\scripts\Preflight-Antivirus.ps1 -AutoFix`.

Порядок обработки сервисной разработки — как у задач: план, фиксация после каждого этапа, знания в `opencode-mcp`.

## 8. Добавление общего правила по команде «ЗАПОМНИ»

При команде «ЗАПОМНИ» модель анализирует, нужно ли правило всем сессиям (статическое) или это разовый опыт (динамическое).

| Тип правила | Куда писать |
|-------------|-------------|
| Правило кодировки, BOM, bash | Файл: `C:\AIS\AI\Prod\AGENTS.md` или `C:\AIS\AI\Prod\.opencode\preflight.mdc` |
| Особенность объекта PowerBuilder | Файл: `C:\AIS\AI\Prod\.opencode\pb-object-rules.mdc` |
| Особенность SQL и Sybase | Файл: `C:\AIS\AI\Prod\.opencode\sql-rules.mdc` |
| Ошибка с решением (баг) | Файл: `C:\AIS\AI\Prod\rules\changelog.md` (Bug-NNN) |
| Термин, сокращение | Файл: `C:\AIS\AI\Prod\rules\abbreviations.md` или `C:\AIS\AI\Prod\.opencode\glossary.mdc` |
| Команда OpenCode | Файл: `C:\AIS\AI\Prod\AGENTS.md` (таблица команд) |
| Настройка провайдера | Знание в `opencode-mcp` |
| Опыт исправления ошибки WPF или PowerShell | Знание в `opencode-mcp` |
| Опыт работы с задачей | Знание в `ais-catalog` |

Критерий выбора: если правило должны знать все будущие сессии — файл; если это опыт конкретной ситуации — знание в базе.

## 9. Сохранение знаний и остановка задачи

Правило остановки применяется при любой долгой задаче, когда следующий шаг требует решения аналитика или ресурс модели исчерпан.

1. Не продолжать самостоятельно, если нужен выбор варианта или сверка постановки.
2. Сохранить всё по правилу «Знания в первую очередь»:
   - сводная запись в `ais-catalog` (анализ, вывод, карта воздействия, точка возобновления с командой продолжения);
   - бизнес-правило в `ais-catalog` при необходимости;
   - файлы задачи в `Describe\` (анализ и план реализации).
3. Статический якорь — запись в `C:\AIS\AI\Prod\rules\pending-tasks.md` (видна без баз знаний).
4. Синхронно свести статус с планом задачи и списком задач сессии.
5. Записи в базу знаний писать одной сводной записью на задачу, не дробить; использовать явные теги; проверять дубли перед сохранением.

- [ ] Выгружены оригиналы (SQL из `dev_golden`, PB — копия из библиотеки).
- [ ] Создан план реализации с этапами и «СЛЕДУЮЩИМ ШАГОМ».
- [ ] План продублирован в `ais-catalog` и `C:\AIS\AI\Prod\rules\pending-tasks.md`.

### 10.2. Продолжение задачи

- [ ] Получена явная команда «продолжить <имя>».
- [ ] Выполнен поиск в базе знаний по тегам задачи.
- [ ] Прочитаны `Describe\` и план реализации.
- [ ] Определён «СЛЕДУЮЩИЙ ШАГ».
- [ ] Работа идёт только в папке задачи.

### 10.3. Остановка задачи

- [ ] Зафиксирован результат текущего этапа.
- [ ] Обновлён план реализации (статусы, «СЛЕДУЮЩИЙ ШАГ»).

- [ ] Обновлён `C:\AIS\AI\Prod\rules\pending-tasks.md`.
- [ ] Синхронизирован список задач сессии.

### 10.4. Подготовка документации

- [ ] Файл `.md` — UTC-8 без BOM.
- [ ] Сформирован `.html` (инлайн-стили, белый фон, тёмный текст).
- [ ] Сформирован `.pdf` (через Edge или конвертер).
- [ ] Язык — только русский, без сокращений и серого текста.
