1. Назначение

Портативный набор скриптов для экспорта объектов БД Sybase ASE 15.5 и PowerBuilder, проверки готовности к выводу в промышленную эксплуатацию, и создания задачи RFC в Jira.

Портативность: Проект организован так, что копированием корневой папки весь функционал может быть перенесен на другой компьютер или использован в другом проекте. См. раздел 12. Развертывание и перенос.

2. Быстрый старт

Запустите главный скрипт-оркестратор. Он запросит пароль Sybase и наименование задачи, затем покажет меню:

prepare_release.bat

Или используйте графический интерфейс (рекомендуется):

powershell -ExecutionPolicy Bypass -File C:\AIS\AI\Prod\Prod-GUI.ps1

3. Параметры (везде)

Пароль Sybase (PASSWORD) — нигде не хранится в файлах. Вводится при каждом запуске:

  • В prepare_release.bat — при запуске
  • В bat-скриптах — как параметр командной строки
  • В ps1-скриптах — как параметр -Password или интерактивный запрос

Наименование задачи (TaskName) — Jira-идентификатор (например, SYBASE-19337 или SUPRT-15514). Передаётся во все скрипты для логирования и создания RFC.

   4 - Выгрузка PB: Current или Main
   5 - Выгрузка SQL: Current (dev_golden)
   6 - Выгрузка SQL: Main (galaxy)
   7 - Выгрузка SQL из папки Ready
   8 - Создание RFC в Jira
   9 - VSS: Получить последнюю версию
  10 - VSS: Проверить статус

5.2. Полный экспорт — SQL_exp_param.bat

Экспортирует все объекты указанного сервера и БД:

SQL_exp_param.bat <server> <database> <password> <task_name>

Пример:

SQL_exp_param.bat dev_golden golden PASSWORD SYBASE-19337

Создаёт структуру папок BD\<server>\<database>\Procedure\ и т.д.

Примечание: Процедуры, функции и триггеры экспортируются через syscomments. Объекты с одинаковым именем на разных схемах (dbo, web) перезаписывают друг друга.

5.3. Экспорт одного объекта — SQL_exp_single.bat

SQL_exp_single.bat <type> <object_name> <server> <database> <password> [task_name]

Пример:

SQL_exp_single.bat Procedure check_agent dev_golden golden PASSWORD SYBASE-19337

Типы: Procedure, Function, Trigger, Table, Index, PK, FK, Grant.

5.4. Экспорт по папке Ready — SQL_exp_ready.bat

SQL_exp_ready.bat <ready_folder> <password> [task_name]

Пример:

SQL_exp_ready.bat C:\Temp\ReadyMerged\SYBASE-19337 PASSWORD SYBASE-19337
Важно: Имя файла (без расширения) используется как имя объекта для object_id(). Файл должен называться точно как объект в БД.

Структура папки Ready:

ReadyFolder\
  dev_golden\
    golden\
      Procedure\check_agent.sql
      Procedure\usp_add_entity_data.sql
      Functions\fn_calc_sum.sql
      Triggers\trg_after_insert.sql

5.5. Сравнение и отчёт — Compare-Export.ps1

powershell -ExecutionPolicy Bypass -File Compare-Export.ps1 [-Password <pass>] [-TaskName <task>] [-ShowDiff] [-CreateRFC]
ПараметрОписание
-PasswordПароль Sybase (если не указан — запросит)
-TaskNameИдентификатор задачи Jira
-ShowDiffОткрыть TortoiseMerge для различающихся файлов
-CreateRFCПринудительное создание RFC (без подтверждения)

После проверки скрипт предлагает создать RFC в Jira, если все объекты READY.

5.6. Создание RFC — Create-RFC.ps1

powershell -ExecutionPolicy Bypass -File Create-RFC.ps1 -TaskName SYBASE-19337 [-Force]

Автоматически проверяет, существует ли уже RFC для данной задачи (поиск по summary, description и task_link_field). Если существует — пропускает создание.

Параметры RFC:

  • Время начала релиза: текущее время + 1 час, минуты и секунды округлены до 0
  • Время завершения релиза: время начала + 24 часа
  • RFC связывается с оригинальной задачей через issue link (Relates)

5.7. Настройка Jira — Find-JiraFields.ps1

Скрипт для обнаружения ID пользовательских полей Jira. Необходим для настройки config.json:

powershell -ExecutionPolicy Bypass -File Find-JiraFields.ps1

Показывает все кастомные поля Jira. Найдите поля "Время начала релиза" и "Время завершения релиза" и запишите их ID в config.json.

5.8. Тестирование — test_sql_export.ps1

powershell -ExecutionPolicy Bypass -File test_sql_export.ps1 [-Password <pass>] [-TaskName <task>]

Проверяет: наличие файла, заголовок CREATE, отсутствие ошибок isql, совпадение хеша, кодировку cp1251, отсутствие BOM.

5.9. Сравнение PB: Current и Main — Compare-PB.ps1

powershell -ExecutionPolicy Bypass -File Compare-PB.ps1 [-ConfigPath <config.json>] [-OutputFile <report.txt>]

Операции выгрузки SQL

Три операции выгрузки объектов из базы данных Sybase ASE через утилиту isql:

  • Выгрузка SQL: Current (dev_golden) — полный экспорт всех процедур, функции и триггеров с сервера dev_golden (рабочая версия БД). Сохраняет файлы в BD\dev_golden\golden\. Запускает скрипт SQL_exp_param.bat.
  • Выгрузка SQL: Main (galaxy) — полный экспорт с сервера galaxy (промышленная версия БД). Сохраняет в BD\galaxy\golden\. Запускает SQL_exp_param.bat.
  • Выгрузка SQL из папки Ready — экспорт только тех объектов, файлы которых лежат в папке Ready_* задачи. Для каждого файла определяется тип (Procedure/Function/Trigger) и запускается isql с DDL-запросом к серверу dev_golden. Запускает SQL_exp_ready.bat.

Параметры: Server, Database, Password. Пароль обязателен.

Сравнение и проверка (Compare & Verify)

Запускаемый скрипт: Compare-Export.ps1

Назначение: проверка готовности объектов задачи к выводу в ПРОД. Сравнивает файлы из папок Ready_* задачи с эталонными копиями Current и Main, генерирует отчёт и (опционально) создаёт RFC в Jira.

Что делает:

  1. Слияние папок Ready — все файлы из всех папок Ready_* задачи копируются в C:\Temp\ReadyMerged\<TaskName>\. Более свежие файлы перезаписывают старые.
  2. Сравнение каждого объекта — для каждого файла из слияния вычисляется MD5-хэш и сравнивается с файлами из Current (PB_Current / BD\dev_golden) и Main (PB_Main / BD\galaxy).
  3. Определение статуса:
Статус в ОДЗначениеОписание
ГОТОВОOKОбъект есть в Current и совпадает с ним. Отличается от Main (или отсутствует в Main — новый объект).
НЕ ГОТОВОНЕТ В CURRENTОбъект не найден в папке Current-экспорта. Автообновление: скрипт пытается скопировать .sr* файл из исходной папки C:\Work\gold. Если не находит — пробует PblDump.exe из PBL.
НЕ ГОТОВООТЛИЧАЕТСЯ ОТ CURRENTФайл в Ready отличается от файла в Current. Рекомендуется проверить различия через TortoiseMerge.
НЕ ГОТОВОСОВПАДАЕТ С MAINФайл в Ready совпадает с Main-версией, но отличается от Current. Объект требует проверки.
—НОВЫЙ ОБЪЕКТОтсутствует в Main-экспорте (создан впервые). Не является самостоятельной причиной "НЕ ГОТОВО", указывается дополнительно.
  1. Автообновление — если объекты отсутствуют в Current, скрипт ищет их .sr* файлы в C:\Work\gold. Если найдены — копирует в PB_Current и повторяет сравнение. Если не найдены — пробует PblDump.exe. Результаты повторного сравнения выводятся отдельно.
  2. Диалог сравнения (Show-DiffSelectWindow) — если после проверки остались неготовые объекты, которые можно сравнить (есть файл в Current или Main), в ОД открывается окно с таблицей объектов. Кнопки: Сравнить выбранные, Сравнить всё, Закрыть. При нажатии запускается TortoiseMerge с аргументами /base <базовый> /mine <готовый>.
  3. Отчёт — сохраняется в release_report.txt с таблицей статусов и Jira-таблицей.
  4. Создание RFC — если все объекты ГОТОВЫ, скрипт предлагает создать RFC (или создаёт принудительно при флаге -CreateRFC).

Параметры: Task Name (Jira) обязателен. Password для доступа к БД. Чекбоксы: Show differences (автозапуск TortoiseMerge), Create RFC (без запроса).

Создание RFC в Jira

Создаёт задачу типа RFC в Jira, привязывая её к задаче разработки. VSS-операции

Для работы с Microsoft Visual SourceSafe (VSS) добавлены 6 операций. При выборе любой VSS-операции отображаются поля ввода:

  • VSS DB Path — путь к файлу srcsafe.ini базы данных VSS
  • VSS Username — имя пользователя VSS
  • Объект VSS ($/) — путь к проекту/файлу в VSS. Поддерживает краткое имя (автоматический поиск в PB_Main/PB_Current)

Пароль VSS не вводится в операции — он задаётся один раз в панели Settings → VSS (шифруется AES-256 с мастер-ключом Windows DPAPI). Поле пароля Sybase также скрыто для VSS-операций.

Операции Checkout и Checkin дополнительно содержат поле комментария. Операции Get Latest, Check Status, Checkout, Checkin и Undo Check Out поддерживают флаг Recursive для рекурсивной обработки подпроектов.

Операция Check Status имеет поле Task Name (Jira) — при его заполнении объекты берутся из папок Ready_* задачи (исключая пустую папку Ready_), для каждого выполняется проверка статуса VSS, а результат показывается в окне с таблицей и кнопками Checkout (для свободных) и Undo Checkout (для занятых текущим пользователем). Поле Task Name (Jira) является редактируемым ComboBox с историей последних введённых значений (общая для всех операций). История сохраняется между сеансами, макс. количество настраивается в панели Settings.

При проверке статуса обычным способом (без TaskName) в popup-результате отображается имя пользователя, занявшего объект (например "Занят: vchaga (3)").

Операция VSS: Undo Check Out снимает резервирование объекта, возвращая его в исходное состояние без сохранения изменений. Поле комментария не требуется.

5.13. Панель настроек (Settings)

Операция "Настройки параметров" (индекс 0) открывает панель управления конфигурацией проекта прямо в GUI. Панель позволяет просматривать и редактировать все параметры из config.json без ручного редактирования файла.

Группы настроек

  • Пути к исходникам PowerBuilder — Main source (C:\SRC125\gold), Current source (C:\Work\gold)
  • Пути к экспортам — PB Main/Current export, SQL Current/Main export
  • Пути к релизам — Release root, ReadyMerged root
  • Настройки VSS — DB Path, Username, Password (расшифровывается из хранилища), Project, История: макс. объектов
  • Настройки GUI — Таймаут вывода (сек), История Task Name: макс. значений
  • Утилиты — TortoiseMerge, PblDump

Действия

  • Сохранить — записывает изменения в config.json с шифрованием пароля VSS
  • Сбросить — перезагружает настройки из файла
  • Проверить пути — валидирует существование и права доступа для всех указанных путей
  • Экспорт — выгружает настройки + историю изменений в JSON-файл
  • Импорт — загружает настройки из JSON-файла с созданием резервной копии

Шифрование пароля VSS

Пароль VSS шифруется алгоритмом AES-256 с использованием мастер-ключа, защищённого Windows DPAPI (Data Protection API). Мастер-ключ уникален для каждого пользователя и компьютера. При первом открытии панели настроек мастер-ключ создаётся автоматически.

  • Пароль расшифровывается только для отображения в поле ввода
  • В конфигурационном файле хранится только зашифрованная строка (password_encrypted)
  • При копировании проекта на другой компьютер мастер-ключ необходимо создать заново (происходит автоматически при открытии Settings)

Валидация путей

Кнопка "Проверить пути" анализирует каждый путь из конфигурации и показывает статус:

  • ✓ Существует — путь найден, есть права доступа
  • ✗ Не найден — путь не существует
  • ⚠ Нет прав выполнения — для утилит (TortoiseMerge, PblDump)
  • ⚠ Только чтение — для папок без права записи

Журнал изменений

Все изменения настроек записываются в config/settings_history.json (до 50 последних записей) с указанием даты, параметра, старого и нового значения.

5.14. Комментарий в Jira — Add-ReleaseComment.ps1

Скрипт сканирует папки Ready_* указанной задачи Jira (-TaskName SYBASE-xxxxx), собирает все объекты PowerBuilder (.sr*) и SQL (.sql) из latest-версий папок Ready, и добавляет комментарий к задаче Jira с таблицей этих объектов в формате Jira-вики.

Назначение: Просмотр истории версий VSS для выбранного объекта PowerBuilder.

Основные возможности:

  • Версия — номер версии
  • Пользователь — кто выполнил действие
  • Дата / Время — когда выполнено действие
  • Действие — Checked in, Created, Destroyed и т.д.
  • Комментарий — комментарий к версии
  • Найдено — галочка, если искомый текст найден в содержимом файла версии

2. Поиск контекста в версиях

В верхней части окна расположена строка поиска:

  • Введите искомый текст (например, имя подпрограммы или переменной)
  • Нажмите Enter или кнопку ▼ — запускается VSS-поиск по содержимому каждой версии
  • Ход поиска отображается двумя прогресс-барами (верхний — общий прогресс, нижний — текущая версия)
  • Курсор меняется на песочные часы во время поиска
  • После завершения найденные версии отмечаются галочкой в колонке «Найдено»
  • Счётчик слева от строки поиска показывает: текущая_позиция — всего_найдено
  • Кнопки ▼ (Enter) и ▲ (Shift+Enter) — навигация по найденным строкам

3. Сравнение двух версий (TortoiseMerge)

Чтобы сравнить две версии объекта:

  1. Выберите две строки в таблице (Ctrl+Click или Shift+Click)
  2. Нажмите кнопку «Сравнить выделенные (TortoiseMerge)»
  3. Откроется TortoiseMerge, показывающий различия между файлами версий
  4. Если перед сравнением выполнялся поиск контекста — TortoiseMerge автоматически перейдёт к строке с найденным текстом

Примечание: Для работы сравнения требуется установленный TortoiseSVN (TortoiseMerge.exe в C:\Program Files\TortoiseSVN\bin\).

Использование: для планирования очередности операций и оценки времени — какие шаги можно делать параллельно (экспорты), какие строго последовательны.
4 Распределение операций по категориям Круговая диаграмма (Pie) 18 операций GUI, сгруппированных по 6 категориям: Экспорт (4), Сравнение (3), VSS (6), Jira (2), Утилиты (2), Настройки (1).
Использование: для быстрой оценки функционального покрытия сервиса — какая доля операций приходится на каждую категорию.
5 Зависимости между операциями Диаграмма классов Какие операции должны быть выполнены до запуска других. Settings — обязательный первый шаг. Экспорт должен предшествовать сравнению. Compare & Verify → Create RFC → Release Comment.
Использование: для определения порядка запуска — нельзя сравнивать объекты, не экспортировав их предварительно.
6 VSS-операции Sequence diagram Взаимодействие: Пользователь → GUI → VSS-Utils.ps1 → ss.exe → VSS Database. Показаны все 5 команд (Get, Status, Checkout, Checkin, Undo) с расшифровкой пароля из config.json.
Использование: для понимания потоков вызовов и данных при работе с VSS — где расшифровывается пароль, как передаётся в ss.exe, как возвращается результат.
7 Интеграция с Jira Sequence diagram Два процесса: создание RFC (JQL-поиск, вычисление окна релиза, POST issue, issueLink) и добавление комментария с таблицей объектов (сканирование Ready_*, определение библиотек PB, формирование wiki-таблицы 4 колонки, POST comment).
Использование: для понимания API-вызовов Jira и алгоритма формирования таблицы — откуда берутся значения для каждой колонки.
8 Compare & Verify: состояния объектов State diagram Все статусы проверки (READY, NOT_READY, SAME_AS_MAIN, NOT_IN_CURRENT, NEW_OBJECT) и переходы между ними. Показаны ветви автообновления (PblDump) и визуального сравнения (TortoiseMerge).
Использование: для понимания логики проверки — при каких условиях объект получает тот или иной статус и какие действия следуют.
9 Полный список операций GUI Таблица 18 операций с параметрами, категорией, типом пароля и целевым скриптом.
Использование: как справочник — какая операция какой скрипт вызывает и какие параметры требует.

Как использовать диаграммы

  1. При первом знакомстве с сервисом: начать с раздела 1 (Архитектура, C4 Container) для понимания компонентов, затем раздел 3 (Гант) для последовательности работы.
  2. При поиске ошибки в потоке данных: раздел 2 (ER-диаграмма) — трассировка пути файла от источника до отчёта.
  3. При планировании релиза: раздел 3 (Гант) — очередность и параллельность этапов.
  4. При проблемах с VSS: раздел 6 (Sequence) — потоки вызовов ss.exe.
  5. При проблемах с Jira: раздел 7 (Sequence) — API-вызовы и формирование таблицы.
  6. При непонятном статусе объекта: раздел 8 (State) — условия и переходы статусов.
