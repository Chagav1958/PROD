# Техническая спецификация: Сервис «ЭКСТРА»

## 1. Назначение

> **Гибрид (важно):** Если в этой или предыдущей сессии была запущена команда `TASK` и идёт выполнение требований ТЗ — «ЭКСТРА» может быть запущена **как подрежим TASK-сессии** (срочный SELECT-анализ БД для поиска решения по ТЗ, когда критически не хватает времени). Это не обязательно отдельный сервис; см. также `rules/extra-rules.md` → «Гибрид TASK» и `rules/sborka-rules.md` (СБОРКА — аналогично).

Сервис **«ЭКСТРА»** — срочный однодневный режим работы для задач типа `SYBASE-*`, `SUPRT-*`, произвольных задач TASK.

Режим действует **только один день** — дату, объявленную как «ЭКСТРА». Это исключение из стандартных ограничений, позволяющее LLM выполнять команды SQL на сервере для анализа в критической ситуации.

## 2. Область применения

| Параметр | Значение |
|----------|----------|
| Типы задач | `TASK`, `SYBASE-*`, `SUPRT-*` |
| Категория | Срочный режим (1 день) |
| Активен | Только в день, объявленный «ЭКСТРА» |
| Разрешение | Выполнение ограниченного набора SQL-запросов |

## 3. Строгие ограничения

### 3.1. Тип команды — ТОЛЬКО SELECT

**Категорически запрещены ЛЮБЫЕ команды, кроме чтения:**

| Разрешено | Запрещено |
|-----------|-----------|
| `SELECT` (только чтение) | `INSERT`, `UPDATE`, `DELETE` |
| — | `CREATE`, `ALTER`, `DROP` |
| — | `TRUNCATE`, `GRANT`, `REVOKE` |
| — | `EXEC` / `EXECUTE` любых процедур |
| — | Вызов хранимых процедур с побочными эффектами |
| — | `BEGIN TRAN` / `COMMIT` / `ROLLBACK` |
| — | Любые DDL, DML, DCL |

> Правило: команда может быть **ИСКЛЮЧИТЕЛЬНО ТОЛЬКО «SELECT ...»** — только для чтения. Исключительно.

### 3.2. Защита конфиденциальной информации

По команде `SELECT` **НЕ должно выводиться** никакой конфиденциальной информации:

| Запрещено выводить | Примеры |
|--------------------|---------|
| Имена клиентов/посредников | `entity_name`, `mid_name`, `insurant` |
| Номера полисов/договоров | `num_agreement` |
| Суммы | `com_sum`, `pp_sum`, `premium_sum` |
| Адреса, телефоны, email | контактные данные |
| Номера счетов | банковские реквизиты |
| Текстовые поля >10 символов | описания, комментарии, названия |

**Минимум текстовой информации** — в крайнем случае допустимы:
- Внутренние ID (`com_id`, `entity_id`, `ag_id`, `os_policy_id`)
- Коды/статусы (`com_type`, `system`, `state`, `business_role`)
- Ссылки (`cover_id`, `mid_name_id`)
- Технические поля (`update_foundation`, `update_user`)
- Текстовые поля длиной **не более 10 символов**

### 3.3. Назначение использования

Режим «ЭКСТРА» используется **только** для:

1. **Анализа** требований ТЗ.
2. **Поиска решений** выполнения требований ТЗ.
3. Случаи, когда **иначе не обойтись** и **время критически не хватает**.

Запрещается использовать «ЭКСТРА» для:
- Праздного интереса и «посмотреть данные».
- Побочных запросов, не относящихся к ТЗ.
- Запросов с полным выводом конфиденциальных данных.

## 4. Порядок активации

```
1. Задача помечается как «ЭКСТРА» с указанием даты (одна дата — один день действия).
2. В этот день разрешены SELECT-запросы по правилам п.3.
3. На следующий день режим автоматически отключается.
```

## 5. Порядок выполнения запроса

```
1. Сформулировать SELECT по правилам безопасности (минимум текстовых полей, без конфиденциальных данных).
2. Выполнить запрос.
3. Использовать результат для анализа/поиска решения.
4. Не публиковать результаты с конфиденциальными данными.
```

## 6. Шаблон безопасного SELECT

```sql
-- Разрешено: только внутренние ID, коды, статусы, ссылки
SELECT
    com_id,          -- внутренний ID (OK)
    com_type,        -- код/статус (OK)
    state,           -- кодовый статус (OK)
    update_foundation,  -- техническое поле (OK)
    LEFT(descr, 10)  -- текстовое поле НЕ БОЛЕЕ 10 символов (крайний случай)
FROM com
WHERE com_id = :com_id;  -- фильтр по внутреннему ID
```

```sql
-- ЗАПРЕЩЕНО: вывод конфиденциальных данных
SELECT
    entity_name,     -- имя клиента — ЗАПРЕЩЕНО
    num_agreement,   -- номер договора — ЗАПРЕЩЕНО
    com_sum,         -- сумма — ЗАПРЕЩЕНО
    address, phone   -- контакты — ЗАПРЕЩЕНО
FROM ...;
```

## 7. Контроль и журналирование

- Каждый запрос в режиме «ЭКСТРА» фиксируется (журнал: дата, задача, текст запроса, результат).
- При нарушении ограничений (не-SELECT, вывод конфиденциальных данных) — режим прекращается.

## 8. Взаимосвязь с другими правилами

| Правило | Влияние |
|---------|---------|
| Безопасность данных в SQL (AGENTS.md) | Усиливается: жёсткий запрет конфиденциальных данных |
| Диагностические SQL-запросы | То же ограничение, что и в «ЭКСТРА» |
| Сервис СБОРКА | Не пересекается (сборка не требует SQL-выполнения) |
