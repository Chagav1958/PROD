# Сервис «СЕРВИС PB» — управление мерами защиты разработки PowerBuilder и SQL

## 1. Назначение

Сервис «СЕРВИС PB» (команда `PBSERV` / `СЕРВИС PB`) управляет **пятью мерами защиты**
разработки PowerBuilder (.sr*) и ASA SQL (.sql). Меры автоматически предупреждают
типичные ошибки LLM: выдуманные константы (`Warning!`), запрещённые идиомы (`iif(`, `??`,
`?.`, `=>`, `Switch(`), неверный формат дат (mdy-ловушка), обход защиты через PowerShell.

**Ключевое свойство:** каждая мера может быть **отключена** (`PBSERV -Off mN`), если она
блокирует разработку. Сервис ведёт статистику срабатываний, чтобы можно было оценить
эффективность каждой меры и принять решение — отменять её или нет.

## 2. Команды

```
PBSERV                              # статус всех мер (включены/отключены)
PBSERV -Off m1                       # отключить меру M1 (снять блокировку)
PBSERV -On  m1                       # включить меру M1 обратно
PBSERV -Lint -Dir <папка>            # прогнать линтер по папке
PBSERV -Stats                        # статистика срабатываний мер
```

Запуск из консоли:

```
powershell -NoLogo -File C:\AIS\AI\Prod\scripts\PB-Service.ps1
powershell -NoLogo -File C:\AIS\AI\Prod\scripts\PB-Service.ps1 -Off m1
powershell -NoLogo -File C:\AIS\AI\Prod\scripts\PB-Service.ps1 -Lint -Dir "C:\AIS\1 Release\SUPRT-19100\Test_2026_09_16__13_50"
```

## 3. Меры защиты

| Мера | Что делает | Как блокирует | Как отменить |
|------|-----------|---------------|--------------|
| **M1** Enforcer + белый список констант | `pb-sql-enforcer.js` блокирует `edit/write` файлов .sr*/.sql без предварительной валидации, а также код с выдуманными перечисляемыми константами messageBox (`Warning!` и др.) и запрещёнными идиомами | Ошибка-блокировка при `edit`/`write` | `PBSERV -Off m1` |
| **M2** Запрет обхода через PowerShell | Правки .sr*/.sql — ТОЛЬКО через `edit`/`write` (их контролирует enforcer). Правка через bash — нарушение. Если обход неизбежен — сначала прогнать линтер | Правило поведения | `PBSERV -Off m2` |
| **M3** Линтер | `Lint-PB.ps1` проверяет папки Test_/Diag_ на идиомы, выдуманные константы, даты в формате ДД.ММ.ГГГГ (mdy), кракозябры. Отчёт: `temp/pb_lint_report.txt` | Предупреждение (exit 1 при находках) | `PBSERV -Off m3` |
| **M4** Обязательная валидация claude_* | Перед правкой .sr*/.sql вызывать `claude_pb` / `claude_sql` — реальная проверка фрагмента + кредиты enforcer | Косвенно: без кредитов enforcer блокирует | `PBSERV -Off m4` |
| **M5** Ждать запуск MCP | Не начинать правки .sr*/.sql, пока `sybase-docs` / `rules-mcp` не поднялись в списке инструментов | Правило поведения | `PBSERV -Off m5` |

## 4. Конфигурация

Файл: `C:\AIS\AI\Prod\config\pb_service.json`

```json
{
  "measures": {
    "m1_enforcer_allowlist": { "enabled": true, ... },
    "m2_no_bash_bypass":     { "enabled": true, ... },
    "m3_linter":             { "enabled": true, ... },
    "m4_mandatory_claude":   { "enabled": true, ... },
    "m5_wait_mcp":           { "enabled": true, ... }
  },
  "stats": { "m1_enforcer_blocks": 0, "m3_lint_runs": 0, "m3_lint_findings": 0, "m4_claude_validations": 0 },
  "history": []
}
```

- `enabled: false` — мера отключена (не блокирует и не предупреждает).
- `stats` — накапливается автоматически (enforcer пишет блокировки M1, линтер — прогоны M3).
- `history` — журнал действий `PBSERV -On/-Off` (последние 100).

Использование `Warning!` приводит к ошибке компиляции PB:
`C0060: Illegal enumerated constant: warning` и каскаду `C0020`. Вместо неё использовать
`Exclamation!` или `StopSign!`.

## 6. Оценка эффективности мер

Команда `PBSERV -Stats` показывает:

- **M1** — сколько раз enforcer заблокировал правку (несуществующая константа / идиома / без валидации). Большое число блокировок с нашими доработками = мера работает. Если блокировки происходят при корректных правках — мера мешает, её стоит отключить.
- **M3** — сколько раз запускался линтер и сколько находок он выдал.
- **M4** — сколько валидаций claude_* выполнено.

Решение об отмене меры принимается на основе этих цифр: если мера не срабатывает
долгое время и не влияет на качество — её можно отключить без ущерба.

## 7. Интеграция с enforcer

Плагин `.opencode\plugins\pb-sql-enforcer.js` читает `config\pb_service.json` при каждом
вызове `tool.execute.before`:

- если `m1_enforcer_allowlist.enabled=false` — enforcer НЕ блокирует правки (ни по кредитам,
  ни по константам, ни по идиомам);
- при блокировке увеличивается `stats.m1_enforcer_blocks`;
- `pb_enforce_status` показывает статус мер M1/M4/M5.
