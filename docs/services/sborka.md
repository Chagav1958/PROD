# Техническая спецификация: Сервис «СБОРКА»

> **Гибрид (важно):** Если в этой или предыдущей сессии была запущена команда `TASK`/`TASK <имя>` и идёт выполнение требований ТЗ — «СБОРКА» может быть запущена **как подрежим TASK-сессии**, для тестирования доработанных по ТЗ объектов (сборка exe, проверка на тестовой среде или galaxy). Это не отдельный однодневный сервис, а вспомогательный этап внутри задачи. См. также `rules/sborka-rules.md` → раздел «Гибрид TASK», и `docs/services/extra.md` (ЭКСТРА — аналогично).

## 1. Назначение

> **Гибрид (важно):** Если в этой или предыдущей сессии была запущена команда `TASK` (`TASK`, `<имя>`) и идёт выполнение требований ТЗ — «СБОРКА» может быть запущена **как подрежим TASK-сессии** для тестирования доработанных по ТЗ объектов (сборка exe + pbd + проверка). Это не обязательно отдельный сервис; см. также `rules/sborka-rules.md` → «Гибрид TASK» и `rules/extra-rules.md` (ЭКСТРА — аналогично).

Сервис **«СБОРКА»** автоматизирует сборку исполняемого файла `golden.exe` и динамических библиотек `*.pbd` из исходных объектов PowerBuilder для задач типа `SYBASE-*`, `SUPRT-*`, произвольных задач TASK.

Цель — получить готовый к передаче тестировщикам комплект: исполняемый файл + библиотеки + вспомогательные файлы (dll, ini, ocx).

## 2. Область применения

| Параметр | Значение |
|----------|----------|
| Типы задач | `TASK`, `SYBASE-*`, `SUPRT-*`, любые проектные задачи |
| Категория | Сборка (Build) |
| Выходной каталог | `Exe_yyyy_mm_dd__hh_mm` |
| Инструмент | PowerBuilder 12.5 (командная строка) |

## 3. Входные данные

1. **Исходные объекты PB** из рабочих библиотек (`PB_Current` / `C:\SRC125\gold`).
2. **Наиболее свежие объекты PB** из папок `Test_yyyy_mm_dd` (готовые, доработанные объекты, подменяющие исходные).
3. **Вспомогательные файлы** из `C:\Work\gold\golden_start\EXE` — `*.dll`, `*.ini`, `*.ocx`.

## 4. Выходной каталог `Exe_yyyy_mm_dd__hh_mm`

Формат имени — по тем же правилам, что и папки `Test_`:

- `Exe_2026_09_14__15_30` — дата и время сборки.
- Если за эту дату папка уже существует — НЕ перезаписывать, а создать новую с суффиксом времени.

Содержимое:

```
Exe_2026_09_14__15_30/
├── golden.exe              — основной исполняемый файл
├── *.pbd                   — все динамические библиотеки
├── *.dll                   — вспомогательные библиотеки (из EXE-набора)
├── *.ini                   — конфигурационные файлы (из EXE-набора)
├── *.ocx                   — ActiveX (если есть)
└── RELEASE_NOTES.txt       — описание сборки (версия, состав, дата)
```

## 5. Процесс генерации exe

Генерация через командную строку PowerBuilder (см. документацию PowerBuilder 12.5 — построение из командной строки, `pbx125.exe` / `pbw125.exe` без GUI).

Общая схема:

```
pbx125.exe <workspace> /build /target <target> /lib <lib> /project <project>
```

### 5.1. Перед генерацией — обновление golden.srj

Файл: объект PB `golden.srj` (библиотека `golden_start`).

| Поле | Требование |
|------|------------|
| `Copyright` | `(c) 10.09.2026 Renaissance Insurance AI` — вместо `10.09.2026` подставляется **текущая дата** |
| `Product version` | Повышается с каждой генерацией exe |
| `File version` | Повышается с каждой генерацией exe (в **двух местах**) |

Повышение версии:
- Строковый формат вида `X.Y.Z` (например `1.0.0` → `1.0.1`).
- Текущее значение читается из `golden.srj`, счётчик увеличивается на 1.
- Дата в Copyright — сегодняшняя.

### 5.2. Генерация

- Сборка `golden.exe` (exe + all pbd).
- Компиляция всех библиотек, входящих в workspace.
- Проверка ошибок компиляции (нет ошибок → сборка успешна).

### 5.3. Копирование вспомогательных файлов

- Из `C:\Work\gold\golden_start\EXE` копируются: `*.dll`, `*.ini`, `*.ocx` (все вспомогательные файлы).
- Копируются в `Exe_yyyy_mm_dd__hh_mm`.

## 6. Режим «СБОРКА GALAXY»

Если указываем **«СБОРКА GALAXY»** — это значит, что сборка будет тестироваться на сервере galaxy, **одновременно с рабочим процессом**.

### 6.1. Ограничение

Мы **НЕ МОЖЕМ вносить изменения в объекты SQL и тестировать эти изменения в galaxy** — нельзя изменять рабочие SQL-объекты.

### 6.2. Правило _CHAGA

Аналоги SQL-объектов создаются с добавлением к имени суффикса **`_CHAGA`**:

| Рабочий объект | Тестовый аналог |
|----------------|-----------------|
| `usp_report_list_multi_m` | `usp_report_list_multi_m_CHAGA` |
| `v_report_detail` | `v_report_detail_CHAGA` |

Требования:

1. Такие объекты (`*_CHAGA`) создаются для тестирования на сервере galaxy.
2. Именно такие объекты вызываются из объектов PB, входящих в сборку.
3. На именно таких объектах проверяется работа.

### 6.3. Порядок для GALAXY

```
1. Экспорт рабочих SQL-объектов из dev_golden.
2. Создание аналогов *_CHAGA.
3. Внесение изменений ТОЛЬКО в *_CHAGA версии.
4. Настройка PB-объектов на вызов *_CHAGA.
5. Сборка exe.
6. Тестирование на galaxy параллельно рабочему процессу.
7. После подтверждения — перенос изменений в рабочие объекты и снятие *_CHAGA.
```

## 7. Структура команд

| Команда | Параметры | Действие |
|---------|-----------|----------|
| `СБОРКА` | — | Обычная сборка exe + pbd + вспомогательные файлы |
| `СБОРКА GALAXY` | — | Сборка для тестирования на galaxy + создание SQL-аналогов `*_CHAGA` |
| `СБОРКА <путь>` | путь к папке Exe | Сборка с указанием места размещения |

## 8. Проверка результата

| Что проверяем | Как |
|---------------|-----|
| Файлы созданы | `golden.exe` существует, не пустой |
| PBD есть | Список `*.pbd` совпадает с библиотеками workspace |
| Версия повышена | `golden.srj` — Product/File version увеличены |
| Дата актуальна | `Copyright` содержит сегодняшнюю дату |
| Вспомогательные файлы | Все dll/ini/ocx из EXE-набора присутствуют в папке |

## 9. Хранение и документирование

- Папки `Exe_yyyy_mm_dd__hh_mm` создаются в корне задачи (та же папка, где `Test_`).
- `RELEASE_NOTES.txt` — обязательный файл: версия, состав, дата, режим (обычная / GALAXY).
- В `Describe\` — запись «СБОРКА YYYY-MM-DD HH:MM: версия X.Y.Z, состав, результат».

### 10.1. Принцип работы (OrcaScript)

- Скрипт `.PBS` (генерация `temp\sborka\sborka_*.pbs`):
  - `start session`
  - `set liblist` — 33 библиотеки из `LibList` файла `gold.pbt` (пути относительные от рабочего каталога)
  - `set application "golden_start\golden_start.pbl" "golden"`
  - `set exeinfo property` — copyright, fileversion, fileversionnum, productversion, productversionnum
  - `build executable "golden_start\golden.exe" "users.ico" "golden_start\golden.pbr" "<PbdFlags>"`
  - `end session`
- `PbdFlags`: `N` для `golden_start.pbl` (компилируется в exe), `Y` для остальных (pbd).
- Комментарии в `.PBS` — только `//` (символ `#` OrcaScript не поддерживает → `Command syntax error`).
- **Критично:** `orcascr125.exe` запускать из рабочего каталога `C:\Work\gold` (относительные пути liblist).
- Запуск from PS: `cmd /c "orcascr125.exe file.pbs > log 2>&1"` (прямой вызов PowerShell ломает захват stdout).

### 10.2. Версия и Copyright

- Версия перед сборкой повышается на 1 в последнем компоненте (X.Y.Z → X.Y.Z+1), читается из `golden.srj` (`PVS`/`PVN`/`FVS`/`FVN`).
- Copyright: `(c) ДД.ММ.ГГГГ Renaissance Insurance AI` (дата — сегодняшняя).

### 10.3. ДО Show-Sborka-GUI.ps1

Параметры формы:
- **Имя задачи** — для папки выгрузки по умолчанию (по правилу TASK: `C:\AIS\1 Release\<имя>` / `C:\AIS\AI\Prod\tasks\<имя>`).
- **Папка выгрузки** — куда класть `Exe_yyyy_mm_dd__hh_mm`; если пусто — автоопределение.
- **Вариант 1** — сухой прогон (dry-run): подготовить `.PBS`, сборку не выполнять.
- **Вариант 2** — сразу собрать exe + pbd (`-RunBuild`).
- Кнопка «Открыть результат» — открыть последнюю собранную папку `Exe_*`.
- Лог + неопределённый прогресс во время сборки (запуск в фоновом потоке, UI не блокируется).

Запуск: `powershell -NoLogo -File scripts\Show-Sborka-GUI.ps1`.
