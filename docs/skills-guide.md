## 1. Что такое скилл (skill) в OpenCode

**Скилл** — это набор инструкций для LLM-агента, который загружается **по требованию**, а не всегда. Каждый скилл — это папка с файлом `SKILL.md`, содержащим фронтmatter (метаданные) и тело инструкций в формате Markdown.

### 1.1. Физическая структура

```
.opencode/
└── skills/
    ├── my-skill/
    │   └── SKILL.md          ← единственный обязательный файл
    └── another-skill/
        └── SKILL.md
```

### 1.2. Формат SKILL.md

```markdown
---
name: my-skill
description: Описание что делает скилл и когда его загружать.
---

# Название скилла

Тело инструкций в Markdown: примеры, правила, ссылки.
```

**Обязательные поля фронтmatterа:**

| Поле | Описание | Пример |
|------|----------|--------|
| `name` | Имя скилла (строчные, через дефис, ≤64 символа) | `pb-object-skill` |
| `description` | Описание: что делает И КОГДА загружать. Ключевые слова в начале | `Используй ТОЛЬКО при работе с объектами PowerBuilder...` |

### 1.3. Как OpenCode находит скиллы

Конфигурация в `opencode.jsonc`:

```json
{
  "skills": {
    "paths": [".opencode/skills"],
    "urls": []
  }
}
```

OpenCode рекурсивно сканирует указанные директории на наличие `**/SKILL.md`. Скиллы из `urls` загружаются при старте.

### 1.4. Как LLM выбирает скилл

1. В промпте пользователя присутствует ключевое слово, совпадающее с описанием скилла
2. LLM видит список доступных скиллов и их описание (список в системном промпте)
3. LLM вызывает инструмент `skill(name="имя-скилла")`
4. OpenCode загружает тело SKILL.md в контекст сессии

## 2. Сравнение: скиллы vs другие механизмы правил

### 2.1. Механизмы правил в проекте AIS

| Механизм | Где лежит | Когда загружается | Пример |
|----------|-----------|-------------------|--------|
| **`.opencode/*.mdc`** | `.opencode/` | **Всегда** (alwaysApply: true) | `preflight.mdc`, `sql-rules.mdc` |
| **`AGENTS.md`** | корень проекта | **Всегда** (instructions в opencode.jsonc) | Ядро правил проекта |
| **Команды** | `.opencode/command/*.md` | По имени команды `/rules` | `cycle.md`, `rules.md` |
| **Плагины** | `.opencode/plugins/*.js` | Всегда (JS-хуки) | `save-prompts.js`, `loop-guard.js` |
| **MCP-серверы** | отдельные процессы | По вызову инструмента | `ais-catalog`, `sybase-docs` |
| **Скиллы** | `.opencode/skills/*/SKILL.md` | **По требованию** (description) | Новые |

### 2.2. Ключевое отличие: загрузка по требованию

```
┌─────────────────────────────────────────────────────────┐
│  ВСЕГДА в контексте (alwaysApply)                     │
│  • AGENTS.md                                            │
│  • preflight.mdc        ← ≈80 строк                   │
│  • russian-language.mdc ← ≈25 строк                   │
│  • knowledge-first.mdc  ← ≈35 строк                   │
│  • save-analysis.mdc    ← ≈25 строк                   │
│  • token-economy.mdc    ← ≈60 строк                   │
│  • sql-rules.mdc        ← ≈120 строк                 │
│  • pb-object-rules.mdc  ← ≈150 строк                 │
│  • vss-rules.mdc        ← ≈80 строк                  │
│  • jira-table-rules.mdc ← ≈50 строк                  │
│  • ... ещё ~10 mdc-файлов                             │
│  ──────────────────────────────────────                │
│  ИТОГО: ≈1000+ строк правил ВСЕГДА в контексте       │
│  ≈ 3000-5000 токенов на каждую сессию                 │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  ПО ТРЕБОВАНИЮ (skills)                                │
│  • pb-object-skill      ← только при PB-задачах        │
│  • sql-skill            ← только при SQL-задачах       │
│  • jira-task-skill      ← только при задачах Jira      │
│  • vss-skill            ← только при работе с VSS      │
│  • sborka-skill         ← только при СБОРКЕ            │
│  • gui-wpf-skill        ← только при GUI/WPF          │
│  • taskplan-skill       ← только при TaskPlan         │
│  • security-skill       ← только при секретах         │
│  ──────────────────────────────────────                │
│  ИТОГО: ≈2000 строк загружаются ТОЛЬКО при нужде      │
│  ≈ 0 токенов, когда не нужны                          │
└─────────────────────────────────────────────────────────┘
```

### 2.3. Экономия токенов

| Сценарий | Без скиллов (всегда в контексте) | Со скиллами (по требованию) |
|----------|----------------------------------|-----------------------------|
| Простой вопрос | 3000-5000 токенов правил | 1000-1500 токенов (только alwaysApply) |
| Задача PB | 3000-5000 токенов | 1000 + 500 (скилл) = 1500 |
| Задача SQL | 3000-5000 токенов | 1000 + 400 (скилл) = 1400 |
| СБОРКА | 3000-5000 токенов | 1000 + 600 (скилл) = 1600 |
| Задача VSS + SQL | 3000-5000 токенов | 1000 + 500 + 400 = 1900 |

**Экономия: 40-70% контекста на правила** — это критично при работе с большими задачами.

### 2.4. Точность: скиллы vs alwaysApply

| Критерий | alwaysApply | skills |
|----------|-------------|--------|
| Доступ к правилам | Всегда | Только при вызове |
| Риск «забыть» загрузить | Нет (всегда есть) | Да (зависит от description) |
| Нагрузка на контекст | Всегда максимальная | Минимальная |
| Гранулярность | Грубая (всё или ничего) | Тонкая (по теме) |
| Контроль LLM | Пассивный (авто) | Активный (выбор) |

**Важно:** критичные правила (язык, безопасность, кодировка) **не должны** быть скиллами — они всегдаApply.

### 3.1. Приоритет 1 — критичные скиллы (создать сейчас)

#### 3.1.1. `pb-object-skill` — Правила PowerBuilder объектов

**Описание:** Загружать при анализе, правке, генерации PB-объектов (.srw, .sru, .srd, .srf, .srm, .srs).

**Выигрыш:** не нужно грузить pb-object-rules.mdc (≈150 строк) для задач, не связанных с PB.

**Содержание:**
- Как работать с event-ами (Click, ItemChanged, etc.)
- Правила call super:: и наследования
- HEX-кодирование русского текста (~n, ~t)
- Правила именования: w_, u_, dddw_
- Одна PBL — одна сущность
- Ссылки на `C:\AIS\AI\Prod\.opencode\pb-object-rules.mdc`

**Пример SKILL.md:**

```markdown
---
name: pb-object-skill
description: Используй ТОЛЬКО при работе с объектами PowerBuilder: анализ .sr* файлов, правка PB-кода, генерация нового кода, рефакторинг PowerScript. Ключевые слова: .sru, .srw, .srd, event, function, call super, PBL, PB объект.
---

# Правила PowerBuilder объектов

## Базовые правила
- Одна PBL — одна сущность (golden_subject, golden_bill и т.д.)
- Не смешивать объекты из разных PBL
- При правке — проверять файловую кодировку Windows-1251

## Event-ы
[содержимое из pb-object-rules.mdc]

## Функции и переменные
[содержимое из pb-object-rules.mdc]

## HEX-кодирование
[содержимое из pb-object-rules.mdc]
```

#### 3.1.2. `sql-skill` — Правила SQL (Sybase ASE)

**Описание:** Загружать при анализе, правке, генерации SQL-кода для Sybase ASE 15.5.

**Выигрыш:** sql-rules.mdc (≈120 строк) не будет загружаться для задач без SQL.

**Содержание:**
- Специфика Sybase ASE 15.5 (min/max, ISNULL, конвертация типов)
- Запрещённые конструкции (iif, ??, ?., =>)
- Правила оформления: отступы, алиасы, WHERE-порядок
- Безопасность данных: только ID, не выводить имена/номера/суммы
- Ссылки на `C:\AIS\AI\Prod\.opencode\sql-rules.mdc`

**Пример SKILL.md:**

```markdown
---
name: sql-skill
description: Используй ТОЛЬКО при работе с SQL Sybase ASE 15.5: анализ .sql файлов, правка хранимых процедур, генерация запросов, дампы. Ключевые слова: SQL, procedure, function, trigger, SELECT, INSERT, UPDATE, CREATE, golden, dev_golden.
---

# Правила SQL для Sybase ASE 15.5

## Специфика ASE
- ISNULL() вместо COALESCE()
- string конкатенация: +
- Дата: getdate(), dateadd(), datediff()

## Безопасность данных
[из sql-rules.mdc — раздел безопасности]

## Оформление кода
[из sql-rules.mdc]
```

**Описание:** Загружать при начале/продолжении/завершении задач SYBASE-*/SUPRT-*, при любых манипуляциях с папками Git_/Test_/Ready_, при ТЗ, PLAN_РЕАЛИЗАЦИИ.

**Выигрыш:** значительная часть AGENTS.md (раздел «Правило TASK») не нужна при обычных вопросах.

**Содержание:**
- Правило TASK: корневые пути, именование сессий
- Правило поиска папки (0a): `<задача>_*` потом `<задача>`

- Правило остановки/продолжения

- Ссылки на `C:\AIS\AI\Prod\AGENTS.md` (разделы TASK, Правило остановки, Стратегия LLM)

name: jira-task-skill

2. **Убрать из alwaysApply** (убрать `alwaysApply: true` или удалить `.mdc`):

   - `jira-table-rules.mdc` → включить в `jira-task-skill`
   - `standard2-gui.mdc` → заменить `gui-wpf-skill`
3. **Оставить alwaysApply** все критичные правила (язык, безопасность, кодировка)

## 6. Дополнительные возможности

### 6.1. Skills через URLs (удалённые скиллы)

Если в будущем понадобится шарить скиллы между проектами:

```json
{
  "skills": {
    "paths": [".opencode/skills"],
    "urls": [
      "https://example.com/opencode-skills/",
      "git@github.com:company/opencode-skills.git"
    ]
  }
}
```

### 6.2. Скиллы как команда (hybrid)

Можно комбинировать: скилл + команда для явного вызова:

```markdown
# .opencode/command/sborka.md
---
description: "Запуск сборки проекта. Формат: СБОРКА [GALAXY|DEBUG]"
---

Загрузи скилл sborka-skill и выполни сборку с параметрами: $ARGUMENTS
```

### 6.3. Скиллы и ссылки (references)

Скиллы могут ссылаться на внешние документы через `references`:

```json
{
  "references": {
    "ais-docs": {
      "path": "docs",
      "description": "Документация проекта AIS"
    }
  }
}
```

Внутри скилла: ` см. @ais-docs/taskplan-guide.md `

## 7. Риски и ограничения

| Риск | Описание | Решение |
|------|----------|---------|
| LLM не вызовет скилл | Нет гарантии, что описание триггерит | Точное front-loading ключевых слов |
| Задержка загрузки | Скилл грузится отдельным вызовом | Приемлемо для не-аварийных задач |
| Дублирование | Частичное дублирование с alwaysApply | Оставить базовые правила alwaysApply, скиллы — детали |
| Версионирование | Скиллы могут устареть | Хранить в git, версионировать через changelog |

## 8. Заключение

**Механизм скиллов — ключ к масштабированию правил проекта** без перегрузки контекста. При текущем объёме правил (≈30+ .mdc-файлов, ≈1000 строк alwaysApply) скиллы позволяют:

- **Экономить 40-70% токенов** на правилах в каждой сессии
- **Повышать точность** — LLM получает только релевантные правила
- **Упрощать поддержку** — каждый скилл изолирован в своей папке
- **Шарить знания** — через `skills.urls` между проектами

**Приоритет:** начать с `pb-object-skill`, `sql-skill`, `jira-task-skill` — они покрывают 80% рабочих сценариев.
