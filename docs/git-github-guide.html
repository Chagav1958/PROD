1. Что такое Git и GitHub (простыми словами)


- Git — программа контроля версий. Она работает локально на вашем компьютере и запоминает

историю изменений файлов: кто, когда и что менял. Позволяет вернуться к любой прежней версии.

- GitHub — сайт (https://github.com), где хранится копия вашего Git-репозитория в интернете.

Это резервная копия, средство обмена и совместной работы.

- Репозиторий (repo) — папка проекта, в которой Git включён (внутри есть скрытая папка .git).

- Коммит (commit) — «снимок» состояния файлов с подписью и комментарием. Это точка истории.

- Ветка (branch) — независимая линия разработки. Обычно main (основная) и временные ветки.

- Remote (origin) — ссылка на удалённый репозиторий (например, на GitHub).

- Push — отправка коммитов на GitHub. Pull — получение изменений с GitHub.

- Clone — копирование репозитория с GitHub на компьютер целиком.


Схема работы:


[Рабочая папка]  --git add-->  [Индекс (staging)]  --git commit-->  [Локальный репозиторий .git]  --git push-->  [GitHub]

                                                                                                        <--git pull--

5. Основные команды Git (с примерами на вашем проекте)


> Все команды ниже выполняются в консоли Git Bash (правый клик в папке C:\AIS\AI\Prod → «Git Bash Here»).

> В примерах используется ваш главный проект.


5.1. Где я и что изменилось


cd /c/AIS/AI/Prod        # перейти в папку проекта (в Git Bash диск указывается как /c/)

git status               # показать: ветка, изменённые/новые файлы

git status -s            # короткий формат

Пример вывода: On branch main, далее список modified: и untracked:.


5.2. Посмотреть историю


git log --oneline -10             # последние 10 коммитов (коротко)

git log --oneline --graph --all   # история веток в виде графа

git show addabcb                  # подробно показать коммит по его хэшу (первые 7 символов)

У вас, например: addabcb Новый сервис, 576fcf4 Файл правил для сокращения.


5.3. Что именно изменилось в файлах


git diff                          # изменения ещё не добавленных в индекс файлов

git diff --stat                   # только сводка (какие файлы и на сколько строк)

git diff HEAD -- docs/git-github-guide.md   # изменения конкретного файла

5.4. Сохранить изменения (коммит)


git add .                         # добавить ВСЕ изменения в индекс (staging)

git add docs/git-github-guide.md  # или добавить конкретный файл

git commit -m "Docs: руководство по Git и GitHub"   # зафиксировать снимок

Правила хорошего коммита:

- один коммит — одна логическая правка;

- сообщение на русском, кратко и по делу (какие изменения и зачем);

- никогда не коммитить секреты (файл .local_secrets.json и т.п.).


5.5. Отправить на GitHub (push)


git push                          # отправить коммиты в origin/main

git push -u origin main           # первый раз для новой ветки (задать отслеживание)

5.6. Получить изменения с GitHub (pull)


git pull                          # скачать и влить изменения из origin/main

git fetch                         # только скачать (без вливания), потом посмотреть: git log HEAD..origin/main

5.7. Ветки


git branch                        # список локальных веток (* — текущая)

git switch -c feature-new-service  # создать ветку и переключиться  (или: git checkout -b ...)

git switch main                   # вернуться на main

git branch -d feature-new-service # удалить ветку (после слияния)

Слияние ветки в main:


git switch main

git pull

git merge feature-new-service

git push

5.8. Отменить изменения


git restore docs/file.md          # отбросить правки в файле (вернуть как было в последнем коммите)

git restore --staged docs/file.md # убрать файл из индекса (после «git add»)

git revert <хэш>                  # создать коммит, отменяющий указанный коммит (безопасно)

git reset --soft HEAD~1           # снять последний коммит, сохранив изменения в рабочей папке

Важно: git reset --hard уничтожает изменения — применять только осознанно.


5.9. Клонирование (получить проект на новый ПК)


cd /c/AIS/AI

git clone https://github.com/Chagav1958/PROD.git PROD_new

5.10. Полезное


git remote -v                     # показать адреса удалённых репозиториев

git remote show origin            # подробно об origin (нужна сеть)

git tag -a v1.0 -m "Версия 1.0"   # поставить тег (метку версии)

git push --tags                   # отправить теги на GitHub

6. Графические инструменты (без консоли)


6.1. TortoiseGit (правый клик по папке)


- Git Commit → main… — выбрать изменённые файлы, написать сообщение, нажать «Commit».

- Git Pull — получить изменения с GitHub.

- Git Push — отправить свои коммиты.

- Git Status — окно со списком изменённых файлов.

- Git Log — просмотр истории (можно правый клик → «Show Log» прямо в папке).

- Diff (двойной клик по файлу в окне Commit/Log) — сравнение версий.

- Иконки-оверлеи на файлах: зелёная галочка — без изменений, красный — изменён, «+» — новый.


Порядок отправки изменений через TortoiseGit:

1. Правый клик по C:\AIS\AI\Prod → Git Commit → main….

2. Отметить галочками нужные файлы, ввести сообщение, «Commit».

3. Правый клик → Git Push → «OK».


6.2. Git Extensions (визуальный клиент)


Правый клик по папке → Git Extensions → открывается окно с историей, ветками, файлами.

Здесь удобно: смотреть граф коммитов, делать Commit/Pull/Push кнопками, разрешать конфликты.


6.3. WinMerge (слияние конфликтов)


Если при git pull возник конфликт, файл помечается как «конфликтующий». Откройте его в WinMerge

(правый клик → WinMerge, либо TortoiseGit → Edit conflicts), выберите нужные строки,

сохраните файл, затем:


git add конфликтный-файл.md

git commit -m "Разрешён конфликт"

Альтернатива SVN (если где-то используется): правый клик → SVN Checkout / TortoiseSVN — это

другая система (Subversion), принцип похож (checkout/update/commit), но команды отличаются.

8. Безопасность (важно!)


1. Секреты только в .local_secrets.json (C:\AIS\AI\Prod\config\.local_secrets.json).

Этот файл добавлен в .gitignore и никогда не попадает в Git/GitHub.

2. В проекте реализован pre-commit hook и утилита очистки (Clean-GitSecrets) — они не дают

закоммитить пароли/токены. Если Git отказал в коммите — значит найден секрет, уберите его.

3. Personal Access Token (PAT) для GitHub: создаётся на сайте (Settings → Developer settings →

Personal access tokens). Хранить токен — только в защищённом месте (не в файлах репозитория).

4. Регулярно проверяйте git status перед push: не попадают ли лишние (большие/секретные) файлы.

5. Правило проекта: config\config.json и config\settings_history.json — без секретов; значения

подстановочные (***), сами секреты — в .local_secrets.json.
