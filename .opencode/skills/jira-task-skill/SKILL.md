# Работа с задачами Jira (TASK)

> Полный источник: `C:\AIS\AI\Prod\AGENTS.md` (разделы «Правило TASK», «Правило остановки/продолжения», «Стратегия решения объёмных задач»)

## Правило TASK — шаги

0. **Корневой путь задачи:** `SYBASE-*`/`SUPRT-*` → `C:\AIS\1 Release`; остальные → `C:\AIS\AI\Prod\tasks`. Явный `<папка>` переопределяет.

0a. **Поиск папки (ОБЯЗАТЕЛЬНО):** сначала искать папку, начинающуюся с имени задачи + суффикс (`<имя>_*`), напр. `SYBASE-19371_19365`. Есть → работаем в ней, новую НЕ создаём. Папку с точным именем создавать ТОЛЬКО если папки с префиксом нет. Суффикс `_<число>` = ключ родительской задачи (в ней ТЗ).

0b. **Описание из Jira:** ПРОВЕРИТЬ, что `jira_get_issue` есть в списке инструментов. Есть → `jira_get_issue(key="SYBASE-NNNN")`. Нет → НЕ искать скрипты, сообщить: «MCP-сервер atlassian не подключился. Проверьте переменную окружения JIRA_PERSONAL_TOKEN и перезапустите OpenCode».

1. Создать/проверить папку задачи (п.0-0a)
2. **Авто-выгрузка оригиналов** в `Git_YYYY_MM_DD` (SQL: `SQL_exp_single.bat` из dev_golden; PB: из `PB_Current\<lib>\` или `C:\SRC125\gold\<lib>\`)
3. `Test_YYYY_MM_DD` — ГОТОВЫЕ объекты для сборки (не DIAG!). Если папка за дату существует — создать `Test_YYYY_MM_DD__hh_mm`
4. `DIAG_YYYY_MM_DD_hh_mm` — объекты для диагностики (с DIAG-N MessageBox) + `ИНСТРУКЦИЯ.md` внутри
5. `Ready_YYYY_MM_DD` — только по команде после тестирования
6. `Read_YYYY_MM_DD` — готовы к ПРОДУКШН
7. `Describe\<объект>.txt` — описания изменений для каждого объекта

**Сессии OpenCode** называть `<ключ> YYYY-MM-DD HH:MM` (напр. `SUPRT-19100 2026-09-10 14:32`). Окно без задачи — `PROD` / `PROD-сервисы`.

## Остановка/продолжение

**Остановка:** при неясности следующего шага (требует решения аналитика) — НЕ продолжать самостоятельно. Сохранить: MCP `ais-catalog_save_knowledge` (анализ, вывод, карта воздействия, точка возобновления) + файлы в `Describe\` + якорь в `C:\AIS\AI\Prod\rules\pending-tasks.md`. Автопродолжение ЗАПРЕЩЕНО.

**Возобновление (по явной команде):**
1. Knowledge First: `ais-catalog_search_knowledge("<задача>")` + `get_business_rules`
2. Прочитать `Describe\` папки задачи
3. Продолжить с раздела «СЛЕДУЮЩИЙ ШАГ» в `ПЛАН_РЕАЛИЗАЦИИ.txt`
4. При смене папки — перенести файлы, обновить ссылки, удалить ошибочную

## Стратегия дешёвых/дорогих LLM

- Объёмная задача (>3 этапов или >3 объектов) → имя + общий план в `ПЛАН_РЕАЛИЗАЦИИ.txt`
- Этапы с чек-боксами: `[ ]` не начат, `[~]` в работе, `[x]` готов, `[!]` отложен на дорогую LLM
- Фиксация после КАЖДОГО этапа (план + MCP — одна сводная запись, не дробить)
- При исчерпании ресурса: зафиксировать этап, НЕ начинать новый, новая LLM продолжает по правилу возобновления
- Непосильные подзадачи → `[!]` + папка `<имя>_SUB_<n>` + бриф `Describe\<имя>_SUB_<n>_бриф.txt`; дорогую LLM запускать ТОЛЬКО с готовым брифом

## Таблица объектов Jira (комментарий к релизу)

> Полный источник: `C:\AIS\AI\Prod\.opencode\jira-table-rules.mdc`

Формат (вики-разметка, 5 элементов, 4 пайпа):

```
||Проект/Сервер||Библиотека/БД||Наименование объекта||Информация||
|AIS|golden_sprw|w_sprw_all|изменены: ue_find, ue_insert|
|dev_golden|golden|check_agent|Процедура. Исправлен расчёт премии|
```

- **PB Проект/Сервер:** `AIS` (параметр ProjectName); **SQL:** сервер из config.json (напр. `dev_golden`)
- **Библиотека/БД:** PB — имя PBL (папка в PB_Current/PB_Main); SQL — имя БД (`golden`)
- **Информация (≤300 символов):**
  - PB: NEWPB (Ready_*) vs OLDPB (Git_*) → сравнение блоков функций/event-ов → `изменены: f1; добавлены: f3; удалены: f4`. Не найден OLDPB → `Новый объект`. Пусто → `Изменений нет`
  - SQL: NEWSQL (Ready_*) vs OLDSQL (Git_*) → построчно → русские комментарии в зонах отличий → `Процедура. комментарий`
- **NEWPB/NEWSQL** — самый свежий из `Ready_*`; **OLDPB/OLDSQL** — из `Git_*` (наибольшая дата)
- **Валидация:** MD5 NEWPB vs PB_Current, OLDPB vs PB_Main; расхождение → таблица статусов
- **Объект в Ready, но не в Git** — поиск OLDPB: Git_* → PB_Main (копия в `TEMP_ГГГГ_ММ_ДД\PB\`) → VSS (см. vss-skill) → иначе «Новый объект»
