# Безопасность секретов и данных

> Полный источник: `C:\AIS\AI\Prod\AGENTS.md` (разделы «Безопасность»)

## Секреты — СТРОГО

- Логины, пароли, токены, API-ключи **категорически не должны попадать в Git и GitHub ни при каких обстоятельствах**
- Значения секретов хранятся ТОЛЬКО в `config\.local_secrets.json` (UTF-8 без BOM) — файл ВСЕГДА в `.gitignore`
- Шаблон `.local_secrets.example.json` хранится в git (только структура, без значений)
- Исполняемые модули берут секреты через `Read-SecretFromConfig` / аналог или как параметры командной строки
- **Никогда** не хранить секреты в файлах, отслеживаемых git; не коммитить зашифрованные `password_encrypted`-значения и маскированные `***` из `config.json` — эти файлы вынесены в `.gitignore`

## Пароли в командах/скриптах

- Пароль с `'` → экранировать `''` (Bug-017)
- Пароли передаются только как параметры командной строки (не в файлах)
- В VSS — пароль зашифрован AES-256 (см. Settings-Module)

## Антивирус (Bug-063/064/065)

| Запрещённый паттерн | Замена |
|---------------------|--------|
| `-ExecutionPolicy Bypass` | `-ExecutionPolicy RemoteSigned` |
| VBS: `WScript.Shell.Run ..., 0, False` (скрытый) | `Shell.Application.ShellExecute ..., "open", 1` |
| `IEX` / `Invoke-Expression` от подозрительных строк | .NET методы |
| `WindowStyle Hidden` | `WindowStyle Normal` |
| Запись .ps1 без BOM | Всегда UTF-8 with BOM |

После записи .ps1 — запускать `scripts\Add-Bom.ps1 <файл>`; при массовых правках — `Preflight-Antivirus.ps1 -AutoFix`.

## Защита данных в SQL-выводах

При диагностических SELECT НЕ выводить: имена (`entity_name`, `mid_name`, `insurant`), номера (`num_agreement`), суммы (`com_sum`, `pp_sum`), адреса, телефоны, email, счета. Разрешено: внутренние ID, коды/статусы, ссылки, техполя. Подробно — в скилле `sql-diagnostics-skill`.
