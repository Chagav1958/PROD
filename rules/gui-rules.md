# rules/gui-rules.md — Правила GUI (WPF интерфейс)

## Баги и исправления

### BUG-004: Stop button использует неверную переменную
**Дата обнаружения:** 19.06.2026
**Симптом:** Кнопка Stop не останавливает процесс
**Причина:** Использовалась `$script:guiProcess` вместо `$script:currentProcess`
**Исправление:** Заменить `$script:guiProcess` на `$script:currentProcess` в обработчике Stop
**Статус:** ✅ Исправлено

### BUG-005: Export-ModuleMember при dot-source
**Дата обнаружения:** 19.06.2026
**Симптом:** Ошибка при dot-sourcing VSS-Utils.ps1
**Причина:** `Export-ModuleMember` работает только внутри модуля
**Исправление:** Добавить проверку `$MyInvocation.MyCommand.CommandType` и `-ErrorAction SilentlyContinue`
**Статус:** ✅ Исправлено

### BUG-006: PowerShell 5.1 не захватывает замыкания в WPF
**Дата обнаружения:** 19.06.2026
**Симптом:** Переменные в callback таймера недоступны
**Причина:** WPF события Add_Tick не захватывают замыкания
**Исправление:** Выносить переменные в `$script:` scope или использовать файловый вывод
**Статус:** ✅ Исправлено

### BUG-007: WPF TextBlock.Text ошибка в PowerShell 5.1
**Дата обнаружения:** 19.06.2026
**Симптом:** `Не удается задать свойство "Text" для объекта типа "System.Windows.Controls.TextBlock"`
**Причина:** PowerShell 5.1 не может установить Text property на TextBlock при создании через `New-Object` в файле с UTF-8 BOM
**Исправление:** Отключить Hint functionality. Использовать `[System.Windows.Media.Brushes]::Black` вместо `BrushConverter`
**Статус:** ✅ Исправлено (Hint отключен)

### BUG-008: ComboBox.Text не работает в WPF через PowerShell
**Дата обнаружения:** 19.06.2026
**Симптом:** Ошибка при установке `$cb.Text = $Default` на editable ComboBox
**Причина:** WPF ComboBox в PowerShell не поддерживает прямую установку Text property
**Исправление:** Добавлять Default значение в Items и устанавливать SelectedItem
**Статус:** ✅ Исправлено

### BUG-009: Порядок кода в Run handler — $checks используется до заполнения
**Дата обнаружения:** 19.06.2026
**Симптом:** `Run error: Не удается индексировать в массив NULL` при запуске VSS-операций
**Причина:** VSS test log код (строка 822) использовал `$checks['Recursive']` до того как `$checks` был заполнен (строка 826)
**Исправление:** Переместить VSS history/test log блок ПОСЛЕ заполнения `$checks`
**Статус:** ✅ Исправлено

### BUG-010: ContainsKey на PSCustomObject
**Дата обнаружения:** 19.06.2026
**Симптом:** `Run error: Сбой вызова метода из-за отсутствия в [System.Management.Automation.PSCustomObject] метода с именем "ContainsKey"`
**Причина:** `ConvertFrom-Json` возвращает PSCustomObject, а не hashtable. Метод ContainsKey() отсутствует у PSCustomObject.
**Исправление:** При загрузке истории конвертировать PSCustomObject в hashtable через цикл по PSObject.Properties
**Статус:** ✅ Исправлено

### BUG-011: ComboBox.Add_TextChanged не существует в WPF
**Дата обнаружения:** 20.06.2026
**Симптом:** `New-ParamComboField ERROR: Не удается найти метод с именем "Add_TextChanged"`
**Причина:** У WPF ComboBox нет метода Add_TextChanged. TextChanged event есть только у TextBox.
**Исправление:** Удалить обработчик TextChanged. Автодополнение временно отключено, ComboBox работает в режиме editable с историей.
**Статус:** ✅ Исправлено

### BUG-013: Дубликат кода Settings handler
**Дата обнаружения:** 20.06.2026
**Симптом:** Дубликат обработчика `$op.HasCustomUI` для Settings (строки 824-846)
**Причина:** Второй блок создавался автоматически, но никогда не выполнялся из-за `return` в первом блоке (строка 821). Во втором блоке отсутствовал параметр `$ProjectRoot`.
**Исправление:** Удалён второй блок, оставлен только первый (с `$ProjectRoot`). 
**Статус:** ✅ Исправлено

## Python/tkinter — STANDARD1 для диалоговых окон (.pyw/.exe)

### Дизайн (полное соответствие СТАНДАРТ1)
- **Окно**: `overrideredirect(True)`, скруглённые углы (18px) через win32 SetWindowRgn, тень через CS_DROPSHADOW
- **Заголовок**: полупрозрачный серый фон (#E8EDF4), 3D-текст (жирный 14px Segoe UI, #1A3A60), перетаскивание, двойной клик = развернуть
- **Кнопки title bar**: ━ (свернуть), ☐ (развернуть/❐), ✕ (закрыть, #E81123) — круглые, hover-эффект (#D0D8E0)
- **Контейнер контента**: тёмно-синяя рамка (#1A3A60, толщина 1), внутри белый фон
- **Поля ввода**: скруглённые рамки, Border = #CBD5E0, ipady=4
- **Info box**: светло-серый фон (#F5F7FA), скруглённый бордер (#CBD5E0)
- **Progress bar**: ttk.Progressbar (determinate), пара: фаза + шаг
- **Кнопки**: градиент тёмно-синий (#1A3A60) → OK, серый (#D0D8E0) → Отмена, hover-эффект
- **Поиск контекста**: поле ввода + счётчик "N - M" + кнопки ▼/▲, Enter = ▼, поиск по всем колонкам Treeview

### Автотестирование
- Все виджеты регистрируются в `_widgets` dict по имени
- `test_click(name)` — программное нажатие кнопки
- `test_set(name, value)` — установка текста поля
- `test_get(name)` — чтение значения поля
- `test_select_combo(name, value)` — выбор пункта ComboBox
- `test_close()` — закрытие окна
- Тестовый скрипт может получать виджеты через `get_widget(name)`

### Компиляция .exe
```powershell
pyinstaller --onefile --windowed --name Show-Название Show-Название.pyw
```
- После компиляции удалить `build\`, `*.spec`
- .exe в `dist\`

### Правила создания нового ДО
1. Наследовать `AppWindow` из `gui_lib.py`
2. Вызвать `super().__init__(title=, width=, height=, resizable=True)`
3. Строить UI в `_build()`
4. Регистрировать все интерактивные элементы через `name=` для автотестов
5. `test_*` методы доступны для внешнего тестирования

### BUG-014: Get-MasterKey failure при первом запуске
**Дата обнаружения:** 20.06.2026
**Симптом:** `Build-SettingsUI` падает с ошибкой в `Get-MasterKey`, панель настроек не отображается.
**Причина:** `ConvertTo-SecureString` на DPAPI-блобе `master_key_encrypted` не работает на другой машине/пользователе. Исключение не обрабатывалось.
**Исправление:** `Get-MasterKey` возвращает `$null` при ошибке. Добавлена `New-MasterKey` для генерации нового мастер-ключа AES-256. `Build-SettingsUI` и `Save-Settings` автоматически создают ключ при его отсутствии.
**Статус:** ✅ Исправлено

## Структура операций

### Формат определения операции
```powershell
@{
    Name = "Internal Name"           # Внутреннее имя (для логов)
    RusName = "Русское название"     # Отображается в ComboBox
    Description = "Описание"         # Показывается под ComboBox курсивом
    NeedsPassword = $true/$false     # Показывать поле пароля Sybase
    Fields = @(                      # Поля ввода
        @{ Name="FieldName"; Label="Лейбл"; Default="значение"; Hint="подсказка" }
    )
    Checkboxes = @(                  # Чекбоксы (опционально)
        @{ Name="CheckName"; Label="Лейбл"; Hint="подсказка" }
    )
    Script = { ... }                 # ScriptBlock для выполнения
}
```

### Поля ввода
- **TextBox** — стандартное поле ввода
- **ComboBox** — для VSS Project с историей (`IsEditable=$true`)
- **PasswordBox** — для пароля Sybase (Show/Hide toggle)

### FEAT-001: VSS Project ComboBox не обновляется после операции
**Дата обнаружения:** 20.06.2026
**Симптом:** После выполнения VSS-операции ComboBox с историей проектов не показывает новый добавленный проект

### BUG-017: Пароль не экранируется в temp-скрипте
**Дата обнаружения:** 20.06.2026
**Симптом:** Если пароль VSS содержит одинарную кавычку (`'`), temp-скрипт ломается (PowerShell синтаксическая ошибка)
**Причина:** Пароль интерполируется напрямую в here-string: `` `$password = '$password' `` — кавычка в пароле закрывает строку
**Исправление:** Добавлено экранирование `$escapedPassword = $password -replace "'", "''"` перед вставкой в скрипт. Также экранируется `$sbText` через `$escapedSbText`.
**Статус:** ✅ Исправлено

### BUG-018: Таймаут 30 секунд для VSS Status -R на $/SRC125 + отсутствие потокового вывода
**Дата обнаружения:** 20.06.2026
**Симптомы:**
1. VSS Check Status с Project=$/SRC125 и Recursive=true → таймаут через 30с (теперь 60с)
2. Во время долгих операций GUI не показывает промежуточных результатов
**Причина:**
1. `ss.exe Status $/SRC125 -R` обрабатывает ~1040 файлов (~33 секунды), таймаут был hardcoded 30с
2. `Invoke-VssCommand` захватывал вывод в `$output` и возвращал массивом; `Out-String` буферизовал всё
3. Таймер таймаута считал от старта процесса, даже если вывод продолжал поступать
**Исправление:**
- Таймаут вынесен в `config.json` (`gui.output_timeout_seconds`, по умолчанию 60)
- В `Launch-GUI.ps1`: таймер использует `$script:uiTimeoutSeconds` из конфига
- В `Settings-Module.ps1`: добавлено поле "Таймаут вывода (сек)" в группу "Настройки GUI"
- В `Save-Settings`: валидация целого числа > 0
- **Streaming:** `Invoke-VssCommand` и все функции VSS-Utils.ps1 больше не захватывают вывод в `$output = & $ssExe` — вывод идёт напрямую в pipeline
- **Streaming wrapper:** Замена `Out-String | Out-File` на `StreamWriter.WriteLine + Flush` — каждая строка пишется сразу
- **Таймаут по бездействию:** `$script:uiLastDataTime` обнуляется при каждом новом выводе; таймаут срабатывает только если нет данных > N секунд
- `config.json`: значение по умолчанию изменено с 30 на 60
- `VSS-Utils.ps1`: все 5 функций переписаны без `$output = ... ; return $output`
**Статус:** ✅ Исправлено

### BUG-019: $_ не экранирован в here-string wrapper'а
**Дата обнаружения:** 20.06.2026
**Симптом:** VSS-операции показывают `Done (exit: 1)` без VSS-вывода в GUI. ss.exe на самом деле возвращает данные (и exit 1 — норма для Status при checked out файлах).
**Причина:** В шаблоне wrapper'а `$_` внутри `ForEach-Object { $sw.WriteLine($_); ... }` не экранирован обратным апострофом в `@" "@` here-string. `$_` интерполировался как `$null` → wrapper генерировал `$sw.WriteLine();` вместо `$sw.WriteLine($_);`. VSS вывод не попадал в output-файл.
**Исправление:** `` `$_ `` в Launch-GUI.ps1.
**Дополнительно:** Удалён мёртвый код (старый wrapper `$wrapperCode`).
**Статус:** ✅ Исправлено

### BUG-020: Update-VssProjectCombo стирает имя объекта из ComboBox
**Дата обнаружения:** 20.06.2026
**Симптом:** После завершения VSS-операции имя объекта (Project) исчезает из ComboBox.
**Причина:** `Update-VssProjectCombo` вызывает `$inner.Items.Clear()`, не сохраняя текущее значение. После перезаполнения Items из истории текущий ввод пользователя теряется.
**Исправление:** Сохранение `$currentText = $inner.Text` перед Clear и восстановление `$inner.Text = $currentText` после.
**Статус:** ✅ Исправлено

### Bug-022: WPF ComboBox .Text не фиксируется при клике на Run
**Дата обнаружения:** 21.06.2026
**Симптом:** При вводе TaskName в editable ComboBox и клике Run — `$params.TaskName` пуст, Script блок идёт в else (обычный Status), результат "Занят"
**Причина:** WPF editable ComboBox не обновляет `.Text` до потери фокуса. `$btnRun.Focus()` не работает, т.к. кнопка уже в фокусе при клике
**Исправление:**
- `$txtLog.Focus()` перед сбором params для VSS Project ComboBox
- TaskName заменён с ComboBox на TextBox — TextBox.Text всегда надёжен
- Prefix-поиск папки задачи при несовпадении имени
**Статус:** ✅ Исправлено
