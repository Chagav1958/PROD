# rules/jira-rules.md — Правила Jira (RFC создание)

## Конфигурация
- Base URL: `https://mytask.renins.com`
- Project Key: `RFC`
- Issue Type: `Change request` (id=5)

## Custom Fields для типа "Change request"
- `customfield_25953` — План проведения работ (textarea)
- `customfield_25954` — План отката (textarea)
- `customfield_25955` — Системы (IT-компоненты) под влиянием (array of issue links)
- `customfield_26053` — Работы планируются с системой (IT-компонентом) (array of issue links)
- `customfield_15258` — Дата начала внедрения (datetime)
- `customfield_15259` — Дата завершения внедрения (datetime)
- `customfield_13852` — Проблемы и риски (textarea)
- `customfield_15254` — Информирование о недоступности (textarea)
- `customfield_15255` — Ответственный за релиз (user)
- `customfield_15256` — Эксперт по продукту (user)
- `customfield_15350` — Проверяющие на бою (array of users)

## Шаблоны текста для RFC

### Summary
```
Разработка - <Название задачи из Jira>
```
Пример: `Разработка - Подсвечивание неактуальных продуктов (спр-к Страховые продукты)`

### Описание (description)
```
RFC сформирована автоматически - AIS Release Preparation
```

### План проведения работ (customfield_25953)
```
1. «Отпускаем»/добавляем (CheckIn) объекты из списка в комментариях к задаче разработки в локальной сборке
2. Заходим на сборочную и «подтягиваем» нужные объекты (при необходимости)
3. Открываем основной объект с версией, переоткрываем pbr и прописываем новую версию и дату (при необходимости)
4. Запускаем Deploy
5. Запускаем соответствующий скрипт c:\SRC125\golden125_deploy.bat
6. Идем на локальную PC и обновляем через Upgrade.cmd и запускаем приложение
7. Нажимаем Ctrl+Alt+V и добавляем версию в список в статусе «рабочая», а существующую ставим в «допустимая»
8. Переносим серверные объекты (хранимые процедуры, триггеры, функции, Виды, таблицы) из списка в комментариях к задаче разработки (при необходимости)
```

### План отката (customfield_25954)
```
Исправляем появившиеся ошибки и собираем новую версию
```

### Проблемы и риски (customfield_13852)

Нет

```

```

### Связь с задачей (issueLink)
- Тип связи: `Mention`
- inwardIssue: RFC (создаваемая)
- outwardIssue: исходная задача (TaskName)

## Скрипты
- `Create-RFC.ps1` — создание RFC задачи
- `Find-JiraFields.ps1` — поиск custom field IDs
- `Compare-Export.ps1` — создание RFC при сравнении

## Правила
- RFC создаётся только при готовности всех объектов
- RFC не создаётся если для задачи уже есть RFC
- Время начала: now + 1h, минуты/секунды = 0
- Время завершения: старт + 24h
- Формат даты: `yyyy-MM-ddTHH:mm:ss.000+0300` (без двоеточия в timezone)
- Исполнитель (assignee) = текущий пользователь (VChaga)
- Проверяющие на бою = автор исходной задачи (reporter)

## Аутентификация
- Используется Bearer token (не Basic Auth)
- Токен хранится в config.json как `token_encrypted`
- Для API Jira Cloud: формат токена — длинная base64-подобная строка

## Кодировка
- JSON отправляется через StreamWriter с UTF-8 BOM
- WebClient.UploadData используется вместо Invoke-RestMethod (проблема с UTF-8)
- Все русские строки должны быть в UTF-8 с BOM
