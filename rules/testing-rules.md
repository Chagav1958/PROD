# rules/testing-rules.md — Правила тестирования и отладки

## Логирование

### Журнал GUI
- Файл: `%TEMP%\ais_gui_debug.log`
- Содержит: события GUI, ошибки, параметры операций
- Используется для отладки проблем с отображением полей

### Журнал выполнения операций
- Временный файл: `%TEMP%\ais_output_<guid>.txt`
- Содержит: вывод скриптов в реальном времени
- Дублируется в область Output GUI

### Журнал VSS-операций
- Файл: `reports\vss_test.log`
- Содержит: вывод VSS команд для тестирования
- Создаётся при запуске VSS-операций

## Методика тестирования VSS

### Параметры тестирования
- **VSS Password:** `12345` (только для тестирования, не сохраняется!)
- **VSS DB Path:** `\\ren-msksf01\VSS2005\srcsafe.ini`
- **VSS Username:** `User`
- **VSS Project:** `$/SRC125`

### Шаги тестирования
1. Запустить GUI: `bin\Launch-GUI.bat`
2. Выбрать VSS-операцию из выпадающего списка
3. Проверить что поля VSS отображаются (VssPath, VssUser, VssPass, Project)
4. Проверить что поле пароля Sybase скрыто (`NeedsPassword = $false`)
5. Ввести пароль VSS: `12345`
6. Ввести путь к объекту VSS
7. Нажать Run
8. Проверить вывод в области Output
9. Проверить журнал `reports\vss_test.log`

### Ожидаемое поведение
- ✅ Поля VSS отображаются при выборе VSS-операции
- ✅ Поле пароля Sybase скрыто для VSS-операций
- ✅ ComboBox для Project показывает историю
- ✅ Вывод дублируется в журнал
- ✅ Нет ошибок "No VSS database found"

## Отладка проблем

### Поля не отображаются
1. Проверить `ais_gui_debug.log` на ошибки BuildParams
2. Проверить структуру операции в `$operations` массиве
3. Проверить что `Fields` не null/empty

### VSS подключение не работает
1. Проверить доступность `\\ren-msksf01\VSS2005\srcsafe.ini`
2. Проверить что SSDIR установлен в каталог (без srcsafe.ini)
3. Проверить пароль VSS (тестовый: 12345)

### Ошибки в выводе
1. Проверить `reports\vss_test.log`
2. Проверить временный файл вывода
3. Проверить `ais_gui_debug.log`
