# rules/testing-rules.md — Правила тестирования и отладки

## ОБЯЗАТЕЛЬНЫЙ ЧЕК-ЛИСТ ПЕРЕД ТЕСТОМ GUI (МОРДА/МОРДА2) — из-за ошибок разных LLM-сессий (см. MCP id=100)

Над GUI-задачей работали РАЗНЫЕ LLM без общей памяти — отсюда повторяющиеся ошибки "проверяем не ту версию". Выполнять ВСЕ пункты перед каждым тестом:

1. **Правка ps1 → перегенерировать .bat**: `.bat-лаунчер (ConvertTo-BatLauncher.ps1) содержит base64-КОПИЮ скрипта`. После ЛЮБОЙ правки Prod-GUI_*.ps1 запустить `powershell -NoLogo -File scripts\ConvertTo-BatLauncher.ps1 <ps1>` — иначе тестируется СТАРАЯ версия.
2. **Убить ВСЕ окна МОРДА2** по `MainWindowTitle -eq 'МОРДА — Подготовка релизов'` (не по CommandLine — у base64-процессов её НЕТ, kill не найдёт). Иначе несколько окон → автотест цепляется за первое/старое.
3. **Перезапустить окно ЗАНОВО** после изменений кода (автотест находит открытое окно и проверяет старую версию).
4. **Запуск GUI**: только через .bat (base64) или Start-Process; `powershell -File GUI.ps1` из bash-инструмента ЗАВИСАЕТ (ждёт закрытия GUI).
5. **WPF Name для UIAutomation**: `.Name` не виден — использовать `[System.Windows.Automation.AutomationProperties]::SetName($el,"...")`.
6. **Долгие операции (сетевой диск)**: Export Service реально ~41 мин (83К файлов на Z:). Per-OP таймаут (быстрые 300с, долгие 900с, сверхдолгие 3000с или SKIP + флаг -IncludeLong). Блокировка UI определяется по UIAutomation-исключениям, а не по таймауту.
7. **Асинхронный Runspace**: EndInvoke ТОЛЬКО после Async.IsCompleted (иначе блокирует UI); Dispose/Close runspace; имя операции для таймера передавать через state (не через замыкание на $op).
8. **PS 5.1**: Start-ThreadJob НЕ существует (PS7+); для фоновых задач — Runspace/Job/Process.
9. **Jira-тест**: ТОЛЬКО чтение (GET myself/projects/issue), если нет явного разрешения на запись (Create RFC / Release Comment создают реальные задачи). PAT → `Authorization: Bearer <base64(userId:secret)>` (Basic даёт 401). Ключ папки с `_суффиксом` (SYBASE-19298_19296) в Jira НЕ существует — читать issue по родительскому ключу (SYBASE-19298).
10. **Учётные данные (пароль БД, токен Jira)**: только параметры командной строки, НЕ записывать в файлы проекта.
11. **Исправленную ошибку ОБЯЗАТЕЛЬНО проверять автономным тестированием** (прямой запуск скрипта без GUI, консольный тест, автотест) — только после подтверждения успеха запускать через GUI. Нельзя «исправил и сразу сдал», не проверив код автономно.

## Команда OUT / ОБР (анализ последнего вывода МОРДА/МОРДА2)

Команда **OUT** / **ОБР** — анализ последнего журнала вывода. Определять, КАКОЙ GUI был активен, по свежести логов:

| GUI | Лог вывода |
|-----|-----------|
| МОРДА (Prod-GUI.ps1 / STANDART1) | `temp\last_output.log` (заголовок `=== AIS Output Log ===`) |
| МОРДА2 (Prod-GUI_STANDART2.ps1) | последний `%TEMP%\tech_journal_*.log` (первая строка `[..] [INFO] MORDA started (ST2)`) |

**Алгоритм при OUT/ОБР:**
1. Взять `temp\last_output.log` и все `%TEMP%\tech_journal_*.log` (созданные за последние ~2 часа).
2. Выбрать лог с самым свежим `LastWriteTime`.
3. Если свежее tech_journal → анализировать его (МОРДА2), иначе → `last_output.log` (МОРДА).
4. Если свежих логов нет — сообщить «нет свежего вывода», не выдумывать.
5. Помощник: `powershell -NoLogo -File scripts\Out-LastOutput.ps1` — выводит путь + содержимое выбранного лога.

## Логирование

### Журнал GUI
- Файл: `%TEMP%\ais_gui_debug.log`
- Содержит: события GUI, ошибки, параметры операций
- Используется для отладки проблем с отображением полей

### Журнал выполнения операций
- Временный файл: `%TEMP%\ais_output_<guid>.txt`
- Содержит: вывод скриптов в реальном времени
- Дублируется в область Output GUI

### Журнал VSS-операций
- Файл: `reports\vss_test.log`
- Содержит: вывод VSS команд для тестирования
- Создаётся при запуске VSS-операций

## Методика тестирования VSS

### Параметры тестирования
- **VSS Password:** `12345` (только для тестирования, не сохраняется!)
- **VSS DB Path:** `\\ren-msksf01\VSS2005\srcsafe.ini`
- **VSS Username:** `User`
- **VSS Project:** `$/SRC125`

### Шаги тестирования
1. Запустить GUI: `bin\Launch-GUI.bat`
2. Выбрать VSS-операцию из выпадающего списка
3. Проверить что поля VSS отображаются (VssPath, VssUser, VssPass, Project)
4. Проверить что поле пароля Sybase скрыто (`NeedsPassword = $false`)
5. Ввести пароль VSS: `12345`
6. Ввести путь к объекту VSS
7. Нажать Run
8. Проверить вывод в области Output
9. Проверить журнал `reports\vss_test.log`

### Ожидаемое поведение
- ✅ Поля VSS отображаются при выборе VSS-операции
- ✅ Поле пароля Sybase скрыто для VSS-операций
- ✅ ComboBox для Project показывает историю
- ✅ Вывод дублируется в журнал
- ✅ Нет ошибок "No VSS database found"

## Отладка проблем

### Поля не отображаются
1. Проверить `ais_gui_debug.log` на ошибки BuildParams
2. Проверить структуру операции в `$operations` массиве
3. Проверить что `Fields` не null/empty

### VSS подключение не работает
1. Проверить доступность `\\ren-msksf01\VSS2005\srcsafe.ini`
2. Проверить что SSDIR установлен в каталог (без srcsafe.ini)
3. Проверить пароль VSS (тестовый: 12345)

### Ошибки в выводе
1. Проверить `reports\vss_test.log`
2. Проверить временный файл вывода
3. Проверить `ais_gui_debug.log`
