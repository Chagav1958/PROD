# Правило ЗАПОМНИ / RULE_MEMBER

## Назначение
При команде `ЗАПОМНИ` или `RULE_MEMBER` — проанализировать, почему последний промпт не был выполнен за один раз, а потребовал нескольких итераций. Установить корневые причины и внести правила в `AGENTS.md` и/или `rules/`.

## Алгоритм работы

1. **Проанализировать историю:** просмотреть последние промпты/запросы пользователя и ответы модели
2. **Выявить причины многократных итераций:**
   - Неполное понимание требований
   - Отсутствие необходимого контекста
   - Ошибки в синтаксисе/кодировке
   - Проблемы с зависимостями
   - Конфликты версий
3. **Сформулировать правило предотвращения:**
   - Конкретное, измеримое, воспроизводимое
   - С указанием файла и строки (если применимо)
4. **Записать правило:**
   - В `AGENTS.md` (если правило общее для всей модели)
   - В `rules/` (если тематическое: `rules/gui-rules.md`, `rules/sql-rules.md` и т.д.)

## Правила для ИИ-модели

1. При получении команды `ЗАПОМНИ` — **немедленно остановить текущую задачу** и перейти к анализу
2. Проанализировать **все сообщения текущей сессии** (не только последнее)
3. Определить **минимум одну корневую причину** (не симптом)
4. Записать правило в формате: `### <дата>: <суть проблемы>` с префиксом `(Правило ЗАПОМНИ)`
5. Обновить `rules/remember-rule.md` при добавлении новых шагов алгоритма
6. Цель: **предотвратить повторение проблемы** при смене модели

## Формат записи нового правила

```markdown
### (Правило ЗАПОМНИ) Дата: ГГГГ-ММ-ДД
- **Проблема:** <краткое описание>
- **Причина:** <корневая причина>
- **Исправление:** <что было изменено>
- **Файл:** <путь к изменённому файлу>
- **Предотвращение:** <правило, предотвращающее повторение>
```

## Задокументированные инциденты

### (Правило ЗАПОМНИ) Дата: 2026-06-27 (2)
- **Проблема:** Тип SQL-объекта не определялся через isql/sysobjects — isql не создавал выходной файл
- **Причина:** Попытка определить тип объекта через запрос к БД (`sysobjects`) вместо чтения текста самого SQL-файла
- **Исправление:** Тип определяется по `CREATE PROCEDURE|FUNCTION|TRIGGER|TABLE|VIEW` в первых строках .sql файла
- **Файл:** `bin/Launch-GUI.ps1` (секция SQL Export с TaskName)
- **Предотвращение:** Тип SQL-объекта определять по содержимому файла (CREATE ...), а не по запросу к БД

### (Правило ЗАПОМНИ) Дата: 2026-06-27 (1)
- **Проблема:** МОРДА не открывалась после правок ОП 7 — ошибка `??` оператор
- **Причина:** Использован `??` (null-coalescing), доступный только в PS 7+, а проект работает на PS 5.1
- **Исправление:** Замена `??` на `if/elseif/else` с `ContainsKey`
- **Файл:** `bin/Launch-GUI.ps1:1843`
- **Предотвращение:** 
  1. После любого изменения `Launch-GUI.ps1` — **запускать скрипт** для проверки синтаксиса
  2. **Не использовать `??`**, `??=` и другие операторы PS 7+ (проект на PS 5.1)
  3. Для проверки синтаксиса запускать скрипт напрямую, а не через `Parser.ParseFile` (ломается экранирование)
